# openHEMA

[![CI](https://github.com/DurandalCode/openHema-3.0/actions/workflows/ci.yml/badge.svg)](https://github.com/DurandalCode/openHema-3.0/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/license-MIT-informational)](LICENSE)

Платформа для проведения турниров по историческому фехтованию (HEMA) —
от регистрации бойцов до живого табло на арене.

Пет-проект, написанный **преимущественно нейросетями**: архитектура,
документация и процесс разработки намеренно устроены так, чтобы агент мог
надёжно ориентироваться в репозитории и вносить изменения самостоятельно —
контракты как источник истины, спецификации перед кодом, TDD-цикл на каждый
инкремент. Подробности подхода — в [AGENTS.md](AGENTS.md).

## Что умеет

- **Турнир и заявки** — профиль турнира, подача заявки бойцом (событийный
  флоу: подача → оплата → подтверждение), правка админом, поиск/фильтры и
  экспорт списков на масштабе.
- **Бойцы и номинации** — учёт бойцов отдельно от аккаунтов, конструктор
  форматов номинации, стадии (пулы → плей-офф).
- **Пулы и жеребьёвка** — распределение бойцов по пулам drag&drop или
  автоматически, генерация пар (round-robin) и порядка боёв.
- **Площадки и ведение боя** — постановка пула на арену, текущий бой,
  быстрый ввод счёта, авто-продвижение по бою/пулу.
- **Публичное живое табло** — состояние боёв, счёт и результаты в реальном
  времени (SSE) без обновления страницы.
- **Пульт турнира** — прогноз очереди и общая оперативная картина по всем
  площадкам; мобильный baseline для админки и ведения боя на телефоне.
- **Аккаунт** — регистрация с подтверждением email, файлы (регламент,
  эмблема), RBAC (admin/user).

Более подробный и живой список — в индексе спецификаций:
[`docs/specs/README.md`](docs/specs/README.md) (каждая фича — своя
`spec.md`/`plan.md`/`tasks.md`).

## Стек

| Слой      | Технология                                      |
| --------- | ------------------------------------------------ |
| Клиент    | Next.js (App Router), TypeScript, pnpm            |
| BFF       | Next.js Route Handlers (Node runtime), REST наружу |
| Транспорт | REST (browser→BFF) · gRPC/Connect (BFF→server)    |
| Сервер    | Go 1.26+, модульный монолит, Connect-Go           |
| Данные    | PostgreSQL · pgx · sqlc · goose                   |
| Контракты | Protobuf, buf → connect-go + connect-es           |
| Auth      | JWT (access+refresh) · argon2id                   |
| Инфра     | docker-compose                                    |

## Быстрый старт

```bash
cp .env.example .env   # задать JWT_*-секреты
make generate           # proto → Go + TS
make sqlc                # sql → sqlc-репозитории
make dev                 # postgres в докере + миграции + server/web локально
```

Альтернатива — весь стек в докере: `make prod`. Полный список команд —
`make help` или таблица в [AGENTS.md](AGENTS.md#команды-см-makefile).

## Структура репозитория

```
/proto      единый источник контрактов (proto + buf)
/server     Go модульный монолит
/web        Next.js: UI + BFF
/deploy     инфраструктурные файлы (compose overrides, init-скрипты)
/docs       архитектура, ADR, спецификации фич
```
