- Статус: draft
- Дата: 2026-08-12
- Спека: `./spec.md`
- Источники решений: `docs/adr/0005-ui-architecture.md` (FSD, next-themes),
  `docs/adr/0006-state-management.md`, `docs/adr/0015-ui-redesign-porting-order.md`

## Обзор решения

Чисто web-слой, без proto/server (NFR-2). Четыре независимых по файлам куска:

1. **Токены фокуса и движения** — `globals.css`: кольцо фокуса перекрашивается
   из брендового красного в контрастный синий дизайна, добавляются токены
   длительностей/кривой переходов.
2. **Новые примитивы `shared/ui`** — подсказка, пагинация, хлебные крошки,
   поле даты-времени, скелетон-композиции, презентационная страница-статус.
3. **Обратная связь** — тост-семейство (единственная новая обязательная
   зависимость, выбор ниже) поверх тонкой проектной обёртки + диалог
   подтверждения поверх `dialog.tsx` из 0022; правило выбора канала
   записывается в `web/AGENTS.md`.
4. **Точечная замена существующих костылей** — два `window.confirm`, поля дат
   турнира, восемь веток загрузки, отсутствующие файлы страниц ошибок и
   редирект-вместо-403 в guard'е админки.

Новых экранов не появляется; ни один экран не переверстывается — правки в
фичах ограничены заменой уже написанного (ветка `isLoading`, вызов
`window.confirm`, два `<Input type="datetime-local">`).

## Web (FSD + BFF)

### 0. Зависимости

| Пакет | Зачем | Решение |
| --- | --- | --- |
| `sonner` | тост-семейство (FR-6) | **добавляем**. Дефолт shadcn, один пакет без периферии; из коробки покрывает все четыре случая спеки: `toast.success`, `toast.error` + `action`, тост с `action` «Отменить», `toast.loading`/`toast.promise`; стек, авто-скрытие, пауза при наведении, `aria-live` и закрытие с клавиатуры — уже внутри. Тему читает из `next-themes` (`useTheme` в нашей обёртке), то есть NFR-1 не нарушается. |
| `react-day-picker` | календарь в поле даты (FR-12) | **добавляем** (тянет `date-fns`). Клавиатурная навигация по сетке месяца, локаль, диапазоны, ARIA — то, что при ручной реализации пришлось бы писать и тестировать самим. Риск и запасной вариант — в «Рисках». |

Альтернативы для тостов, отклонённые: Radix `Toast` из уже установленного
`radix-ui` — примитив помечен legacy и не даёт ни стека, ни `promise`-режима,
пришлось бы писать очередь и таймеры вручную; собственная реализация на
`zustand` — тот же объём работы плюс своя a11y, ради экономии одной
зависимости.

`radix-ui@1.6.1` (уже стоит) экспортирует `Tooltip` и `Popover` — подсказка и
поповер календаря **новых зависимостей не требуют** (проверено по
`node_modules/radix-ui/dist/index.d.ts`).

### 1. Токены — `app/globals.css`

| Токен | Было | Станет | Зачем |
| --- | --- | --- | --- |
| `--ring` | `#e2402c` (бренд, обе темы) | `#8fb0f0` | FR-13/AC-11: сейчас кольцо совпадает с цветом брендовой кнопки и на ней не видно. Значение — из дизайн-файла (`ring: #8fb0f0 · 2px · offset 2px`). |
| `--focus-ring-w` / `--focus-ring-offset` | нет | `2px` / `2px` | толщина и отступ кольца перестают быть магическими числами по компонентам |
| `--motion-fast` / `--motion-base` / `--motion-slow` | нет | `120ms` / `180ms` / `320ms` | FR-13 |
| `--ease-standard` | нет | `cubic-bezier(.2,.8,.2,1)` | FR-13 |

Базовый слой сейчас: `@apply border-border outline-ring/50` — полупрозрачное
кольцо на брендовом цвете было почти незаметным вдвойне; после смены цвета
переводим на полную непрозрачность и токены толщины/отступа.

`--ease-standard` пробрасывается в `@theme inline` (Tailwind v4 генерирует
утилиту `ease-standard` из namespace `--ease-*`). Для длительностей
отдельного namespace в v4 нет — используем переменные напрямую
(`duration-(--motion-base)`); **проверить синтаксис арбитрарного значения на
установленной версии Tailwind при реализации**, не полагаться на память.

### 2. Новые примитивы — `shared/ui/`

| Файл | Основа | API (черновик) |
| --- | --- | --- |
| `tooltip.tsx` | Radix `Tooltip` (есть) | `<Tooltip content>{trigger}</Tooltip>`; Radix открывает подсказку по фокусу штатно — AC-9 закрывается примитивом, а не нашим кодом |
| `pagination.tsx` | презентационный | `page`, `pageCount`, `onPageChange`; `<nav aria-label>`, `aria-current="page"`, неактивные стрелки на границах (FR-10, NFR-3) |
| `breadcrumbs.tsx` | презентационный | `items: {label, href?}[]`; последний — без ссылки, `aria-current="page"` (FR-11) |
| `datetime-field.tsx` | Radix `Popover` (есть) + `react-day-picker` | контролируемый: `value: string \| null` (ISO), `onChange`, `withTime` (FR-12) |
| `skeletons.tsx` | поверх `skeleton.tsx` (0022) | `SkeletonRows({rows, cols})`, `SkeletonCards({count})` — «форма будущего контента» (FR-1) |
| `status-page.tsx` | презентационный | `code`, `title`, `description`, `actions`, `footnote` — общая раскладка страниц 403/404/500 (FR-2/3/4) |
| `confirm-dialog.tsx` | `dialog.tsx` (0022) | `title`, `consequences`, `confirmLabel`, `confirmWord?`, `destructive?`; при заданном `confirmWord` кнопка подтверждения заблокирована до точного совпадения ввода (FR-7) |

Чистая логика выносится из компонентов, чтобы тестироваться без DOM:

- `shared/lib/paginate.ts` — окно номеров страниц с многоточиями
  (`paginationWindow(page, pageCount)`);
- `shared/hooks/use-pagination.ts` — клиентская нарезка массива
  (`{pageItems, page, pageCount, setPage}`), FR-10;
- `shared/lib/datetime.ts` — ISO ↔ значение поля; сюда же переезжает
  `toLocalInput` из `tournament-settings-form.tsx` (сейчас локальный хелпер
  формы).

`AppShell` (0022) принимает `crumb?: string` — **расширяем до
`React.ReactNode`**, чтобы в слот встали хлебные крошки; это единственная
правка компонента из 0022.

### 3. Обратная связь

- `shared/ui/sonner.tsx` — `<Toaster/>` с классами по нашим токенам, тема из
  `useTheme()` (`next-themes`); монтируется один раз в `app/layout.tsx`
  рядом с `AuthDialog`.
- `shared/lib/toast.ts` — **тонкая проектная обёртка**, единственный
  разрешённый вход к тостам: `toastSuccess(msg)`, `toastError(msg, {retry})`,
  `toastUndo(msg, {onUndo})`, `toastPending(msg)`. Зачем обёртка: (а) правило
  FR-5 становится проверяемым на уровне API, а не только на словах;
  (б) `sonner` не расползается импортами по фичам, замена библиотеки — правка
  одного файла; (в) обёртку легко мокать в тестах фич.
- Правило FR-5 записывается в `web/AGENTS.md` (новый раздел «Обратная связь
  и состояния экрана») — там же, где остальные обязательные UI-конвенции, и
  оттуда его читают агенты спек 0024+.

### 4. Страницы ошибок — `app/`

| Файл | Код | Содержание |
| --- | --- | --- |
| `app/not-found.tsx` | 404 | общий текст + переход на главную |
| `app/(admin)/admin/arenas/[id]/not-found.tsx` | 404 | «такой площадки нет» + переход к списку площадок |
| `app/nominations/[id]/not-found.tsx` | 404 | «такой номинации нет» + переход на главную |
| `app/(admin)/admin/nominations/[id]/stages/[stageId]/not-found.tsx` | 404 | «такого этапа нет» + переход к этапам номинации |
| `app/error.tsx` | 500 | клиентский компонент: `reset()` как «Повторить», `error.digest` как копируемый идентификатор |

Сегментные `not-found.tsx` нужны потому, что `notFound()` уже вызывается из
шести страниц, и общий текст «страница не найдена» на удалённой арене хуже
конкретного — Next выбирает ближайший вверх по дереву файл, поэтому точный
текст даётся ровно там, где он известен.

**403** (FR-3): `app/(admin)/layout.tsx` сегодня делает `redirect("/")` для
любого отказа. Разделяем два случая:

```
нет пользователя        → redirect("/login")   (как в /dashboard, /applications)
есть, но не ROLE_ADMIN  → render <StatusPage code="403" …/>
```

Экспериментальный `forbidden()` + `forbidden.tsx` (Next `authInterrupts`)
осознанно не берём — не включаем экспериментальный флаг ради того, что
делается рендером компонента.

### 5. Точечная замена костылей

| Файл | Что меняется |
| --- | --- |
| `app/layout.tsx` | монтируется `<Toaster/>` |
| `features/nomination-pools/ui/nomination-pools.tsx` | `window.confirm` → `ConfirmDialog` (без `confirmWord`: действие покрыто undo); успех → `toastUndo` с «Отменить» поверх существующего undo, ошибка → `toastError` |
| `features/bracket-seeding/ui/bracket-seeding.tsx` | то же для сброса посева |
| `features/tournament-settings/ui/tournament-settings-form.tsx` | два `<Input type="datetime-local">` → `DateTimeField`; локальный `toLocalInput` → `shared/lib/datetime.ts` |
| `features/admin/ui/admin-list.tsx` | локальный `RowsSkeleton` → общий `SkeletonRows` |
| `features/fighter-management/ui/fighter-roster.tsx` | текст «Загрузка…» → `SkeletonRows` |
| `features/my-applications/ui/my-applications-list.tsx`, `features/nomination-management/ui/nomination-management.tsx`, `features/pool-seating/ui/pool-seating.tsx`, `features/bracket-seeding/ui/bracket-seeding.tsx`, `features/stage-management/ui/stage-management.tsx`, `features/format-presets/ui/preset-library.tsx` | существующая ветка `isLoading` → `SkeletonRows`/`SkeletonCards` |

Новых веток загрузки не заводим — только заменяем существующие (иначе это
уже редизайн экрана, то есть спеки 0024+).

- Server components vs client: страницы ошибок — server, кроме `app/error.tsx`
  (обязан быть клиентским). `Toaster`, `ConfirmDialog`, `DateTimeField`,
  `Tooltip`, `Pagination` — клиентские.
- State: тосты — состояние библиотеки; открытие `ConfirmDialog` и ввод слова
  подтверждения — локальный `useState` (ADR 0006, «local»); новых стора и
  запросов не появляется.

## Риски и открытые вопросы

- **`react-day-picker` — главный риск объёма.** v9 сменил API стилизации;
  интеграция с нашими токенами и русской локалью может занять больше, чем
  сам компонент. Запасной вариант, не меняющий публичный API
  `DateTimeField`: собственная сетка месяца поверх Radix `Popover` (даты —
  `Intl.DateTimeFormat`, без `date-fns`). Решение принимается на T-задаче
  поля, не постфактум.
- **Смена `--ring` — визуально сквозная правка.** Токен из 0022 меняется на
  всех экранах сразу; проверять обе темы вручную, а не по одному экрану.
- **`sonner` и тема**: `<Toaster/>` должен читать тему из `next-themes`, а не
  определять её сам, иначе в приложении появится второй источник темы —
  прямое нарушение NFR-1 и границы ADR 0015.
- **`app/error.tsx` перехватывает не всё**: ошибки в самом root layout ловит
  только `global-error.tsx`. Заводить ли его — решить на T-задаче: он требует
  собственных `<html>/<body>` и не наследует стилей приложения, поэтому
  дешёвого переиспользования `StatusPage` там не будет.
- **Тексты 403/404 упоминают роли и сущности** — сверить формулировки с
  реальными названиями ролей RBAC (ADR 0007), а не с текстом дизайн-макета
  («организатор» в макете против `ROLE_ADMIN` в системе).
- `pnpm-lock.yaml` меняется (две новые зависимости) — убедиться, что CI
  ставит их и `pnpm build` проходит.
