# Plan: Кодген контрактов без внешнего реестра плагинов

> Артефакт SDD (ADR 0008). Описывает **КАК** реализуем `spec.md` в архитектуре
> проекта. Заполняется только когда в `spec.md` нет открытых
> `[NEEDS CLARIFICATION]`.

- Статус: ready
- Дата: 2026-09-17
- Спека: `./spec.md`

## Обзор решения

Удалённое исполнение плагинов (`remote: buf.build/...`) заменяется локальными
плагинами, а средой их исполнения становится **отдельный образ кодгена**, а не
хост-машина (решение пользователя 2026-09-17). `make generate` запускает `buf`
внутри контейнера, смонтировав в него рабочую копию; на хосте для генерации не
нужно ничего, кроме Docker, который стеку и так необходим (FR-7).

Ключевое свойство образа — он **не хранит собственный список версий** (FR-8).
Всё, что в нём есть, собирается из манифестов репозитория:

| Инструмент              | Откуда версия                              |
| ----------------------- | ------------------------------------------ |
| `buf`                   | `server/go.mod` (`github.com/bufbuild/buf`) |
| `protoc-gen-go`         | `server/go.mod` (`google.golang.org/protobuf`) |
| `protoc-gen-connect-go` | `server/go.mod` (`connectrpc.com/connect`) |
| `protoc-gen-es`         | `web/package.json` (`@bufbuild/protoc-gen-es`) |

Проверено до написания плана: обе Go-команды собираются в каталоге, где лежат
**только** `go.mod`/`go.sum`, без исходников модуля (0.4 с на тёплом кеше), а
`buf` собирается из той же зафиксированной версии за 3.4 с — то есть слой
образа честно выводится из манифестов и не требует ни `tool`-директив, ни
ARG-ов с продублированными версиями.

Разделение шаблона на «go/ts», заложенное в первой редакции плана, **отменено**:
оно существовало ради того, чтобы окружение без Node могло сгенерировать хотя
бы серверную часть. С образом эта нужда исчезла — Node внутри образа есть
всегда, на хосте не нужен никогда. Остаётся один `proto/buf.gen.yaml`.

## Контракты (proto)

> Источник истины API — `/proto`. Меняем только там, потом `make generate`.

**Ни один `.proto` не меняется** — фича не трогает API (FR-2). Меняется только
конфигурация генерации:

- `proto/buf.gen.yaml` — три плагина переводятся с `remote:` на `local:`,
  по имени бинаря в `PATH` образа:
  - `local: protoc-gen-go` → `out: gen`, `opt: paths=source_relative`
  - `local: protoc-gen-connect-go` → `out: gen`, `opt: paths=source_relative`
  - `local: protoc-gen-es` → `out: ../web/src/gen`, `opt: target=ts`
- `clean: true` и пути сохраняются: `buf` запускается с CWD `/src/server`
  (в контейнере), поэтому `gen` и `../web/src/gen` означают ровно то же, что
  сегодня на хосте.
- `proto/buf.yaml` не меняется; `buf.lock` пуст — внешних BSR-зависимостей у
  модуля нет, так что после фичи обращений к `buf.build` не остаётся вовсе.

## Образ кодгена

`deploy/codegen.Dockerfile`, контекст сборки — **корень репозитория** (нужны и
`server/go.mod`, и `web/package.json`):

1. `FROM golang:1.26-alpine` — копируются только `server/go.mod`/`go.sum`,
   собираются `buf`, `protoc-gen-go`, `protoc-gen-connect-go`
   (`CGO_ENABLED=0`, `GOTOOLCHAIN=local` — как в `server/Dockerfile`).
2. `FROM node:22-alpine` — Go-бинари копируются в `/usr/local/bin`; версия
   `@bufbuild/protoc-gen-es` вычитывается из скопированного
   `web/package.json` и ставится глобально (`npm i -g`).

Слои кешируются по `server/go.mod`/`go.sum` и `web/package.json` — пересборка
происходит только при смене версий, а не на каждый запуск генерации.

Запуск (цель `generate` в Makefile):

```
docker run --rm \
  -u $(id -u):$(id -g) \        # файлы принадлежат хозяину репо, не root
  -v $(CURDIR):/src \           # WORKDIR (/src/server) задан в самом образе
  hema-codegen buf generate ../proto --template ../proto/buf.gen.yaml
```

`HOME=/tmp` и `WORKDIR /src/server` заданы в образе, а не в команде запуска:
`buf` пишет кеш в `$HOME`, а у сквозного uid своего домашнего каталога в
образе нет. Сборка образа идёт с `--network host` — на ВМ у контейнеров нет
DNS-егресса (см. раздел «Риски» и ADR 0023), и без этого сборка виснет.

## Server (модули и слои)

> См. ADR 0002 (модульный монолит) и `server/AGENTS.md`.

Доменных модулей фича не касается: ни `domain/service/repo/api/migrations`, ни
PG-схем, ни wiring. Изменения:

- `server/go.mod` — поднять `google.golang.org/protobuf` до **v1.36.12**.
  Это не косметика: нынешний `server/gen` сгенерирован именно `protoc-gen-go
  v1.36.12` (remote-плагин брал «последний»), при runtime v1.36.11 в `go.mod`.
  Выравнивание даёт и требуемую FR-3 пару «генератор = runtime», и пустой
  дифф в AC-3. `tool`-директивы **не добавляем** — образ собирает плагины
  напрямую из графа зависимостей, а на хосте они не нужны.
- `server/internal/codegen/buf_gen_config_test.go` (новый, тест-онли пакет) —
  страж FR-5/AC-5: читает `proto/buf.gen.yaml` и падает, если у плагина есть
  ключ `remote` или нет `local`, с сообщением-объяснением и ссылкой на
  ADR 0023. Живёт в Go-тестах, потому что путь `proto/**` в path-фильтре CI
  ведёт в те же серверные джобы — страж сработает и на правку самого шаблона.

`server/Dockerfile` и `docker-compose.yml` не меняются: образы по-прежнему
собираются из контекста хоста и ожидают готовый `server/gen` — то есть кодген
обязан отработать до `docker compose build`, что фича и чинит.

## Web (FSD + BFF)

> См. ADR 0005 (UI) и ADR 0006 (state), `web/AGENTS.md`.

Ни одного слоя FSD, ни одного BFF-хендлера фича не трогает. Изменения — в
зависимостях и в одном страже:

- `web/package.json` → `devDependencies`: `@bufbuild/protoc-gen-es` **точной**
  версией `2.15.0` (не `^`): образ ставит ровно то, что здесь написано, и
  «плавающая» версия сделала бы сборку невоспроизводимой.
- `web/package.json` → `dependencies`: `@bufbuild/protobuf` поднять с `^2.12.1`
  до `2.15.0`. Сегодня пара уже разъехалась (кодоген 2.15.0 → runtime 2.12.1) и
  фактически работает; выравнивание — выполнение FR-3 и снижение риска.
- `web/codegen-versions.test.ts` (новый, Vitest) — страж FR-3/AC-9: версия
  `@bufbuild/protoc-gen-es` обязана совпадать с `@bufbuild/protobuf` и быть
  точной. Почему Vitest, а не Go-тест: path-фильтр CI ведёт правку
  `web/package.json` только в web-джобы, и Go-страж на неё бы не запустился.

Отдельный `protoc-gen-connect-es` не нужен: в connect-es v2 сервисные
дескрипторы генерирует сам `protoc-gen-es` (нынешние `*_pb.ts` содержат
`GenService`/`serviceDesc` — подтверждено в сгенерированном коде).

## Оркестрация (Makefile)

Команды пользователя не меняются (FR-6) — меняется, что под ними:

| Цель            | Было                            | Стало                                              |
| --------------- | ------------------------------- | -------------------------------------------------- |
| `codegen-image` | —                               | `docker build -f deploy/codegen.Dockerfile .`      |
| `generate`      | `go tool buf` на хосте          | `buf` внутри образа; зависит от `codegen-image`    |
| `codegen`       | `generate sqlc`                 | без изменений                                       |
| `dev/prod/deploy` | `codegen` первым шагом        | без изменений                                       |
| `sqlc`, `migrate`, `lint-proto` | хостовый `go tool` | **без изменений** — в заблокированный реестр не ходят |

`generate` зависит от `codegen-image` всегда: на неизменных манифестах
`docker build` — это попадание в кеш слоёв (доли секунды), а на изменившихся
образ обязан пересобраться, иначе кодген пойдёт старой версией плагина.

## CI (GitHub Actions)

Сегодня семь джоб независимо выполняют `make generate`. С кодгеном в образе
это означало бы семь сборок образа, поэтому структура меняется на более
дешёвую и заодно менее избыточную, чем нынешняя:

- Новая джоба **`codegen`** — собирает образ (`docker/setup-buildx-action` +
  `docker/build-push-action` с `cache-from/to: type=gha`, `load: true`),
  выполняет `make generate` и `make sqlc`, публикует `server/gen`,
  `web/src/gen` и `server/modules/*/repo/sqlc` как artifact. Запускается при
  любом из трёх path-фильтров (`server`/`web`/`proto`).
- Остальные джобы (`server-build`, `server-vet`, `server-test`,
  `server-test-integration`, `web-test`, `web-tsc`, `web-build`) — `needs:
  codegen`, шаг генерации заменяется на `download-artifact`. Побочный
  выигрыш: генерация в CI выполняется один раз вместо семи.
- `web-eslint` и `proto-lint` не трогаем: первый работает без gen-кода, второй
  использует `buf lint`/`buf breaking`, которые в реестр не ходят.

## Тестирование

> См. ADR 0003 (стратегия) и ADR 0009 (TDD-цикл).

Фича инфраструктурная: «юнитом» здесь является инвариант конфигурации, а
приёмкой — то, что весь существующий тестовый корпус остался зелёным без
единой правки прикладного кода (в этом и есть FR-2).

- **Юнит, red→green** — `server/internal/codegen/buf_gen_config_test.go`
  (нет `remote:`-плагинов) и `web/codegen-versions.test.ts` (версия генератора
  = версия runtime, точная). Оба красные до правок, зелёные после, и оба
  остаются стражами от регресса.
- **Эквивалентность (AC-3)** — эталон снят до правок (29 файлов,
  `protoc-gen-go v1.36.12`, `protoc-gen-es v2.15.0`); после перехода
  `diff -r` эталона с перегенерированным кодом обязан быть пустым.
- **Регрессия корпуса** — `make test-all`, `make test-integration`,
  `go build ./...`, `go vet ./...`, `pnpm exec tsc --noEmit`, `pnpm build`.
  Новых прикладных тестов не пишем: их зелёность на перегенерированном коде и
  есть доказательство FR-2.
- **Приёмка на ВМ (AC-1/AC-2, вручную)** — единственная проверка, которую
  нельзя сделать локально, потому что она и есть исходный баг: на препрод-ВМ
  `git pull` → `make codegen` (сегодня падает `permission_denied: 403
  Forbidden`) → `make deploy`.

## Риски и открытые вопросы

- **Первая сборка образа на ВМ — замерено:** ~6 мин на 2 CPU (образ 447 МБ),
  дальше слой в кеше и `make generate` укладывается в 6.6 с. NFR-1 выполнен.
  Запасной вариант (брать `buf` из образа `bufbuild/buf`, ценой
  продублированной версии) не понадобился.
- **Свойства окружения ВМ, найденные при приёмке** (подробно — в ADR 0023):
  на ВМ нет BuildKit (`buildx` не установлен) — поэтому в Dockerfile нельзя
  `--mount=type=cache`; и у контейнеров там нет DNS-егресса (`DOCKER-USER`
  дропает UDP 53) — поэтому образ собирается с `--network host`. Второе шире
  кодгена: так же не сможет работать любой контейнер, которому нужен интернет
  по имени, включая отправку почты из `server` (спека 0042).
- **Права на файлы из контейнера — проверено на обеих машинах.** С
  `-u $(id -u):$(id -g)` сгенерированное принадлежит хозяину репозитория
  (`danilaorehov:staff` на macOS, `tylys96:tylys96` на ВМ), не root. `HOME`
  задан в самом образе (`ENV HOME=/tmp`), а не в команде запуска: `buf` пишет
  туда кеш, а у сквозного uid своего домашнего каталога в образе нет.
- **Выравнивание версий тянет дифф** `go.sum`/`pnpm-lock.yaml`. Это часть
  FR-3; если подъём `@bufbuild/protobuf` 2.12.1 → 2.15.0 неожиданно ломает
  web-тесты — откатить runtime, оставить точную привязку генератора и
  зафиксировать расхождение в ADR как известное.
- **CI-джоба `codegen` становится узким горлышком**: остальные ждут её. Плата
  за то, что генерация выполняется один раз вместо семи; при неприятном росте
  времени — вернуть генерацию в джобы, но уже с прогретым `type=gha` кешем.
- **Не риск, но к сведению:** в репозитории висит несмерженный worktree
  `.claude/worktrees/local-T5-gate-remaining-public-routes` со старой копией
  `Makefile`/`proto/AGENTS.md` — даёт ложные совпадения при grep'е по репо.
