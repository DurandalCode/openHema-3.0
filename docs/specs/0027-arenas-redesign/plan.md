## Обзор решения

Инкремент **целиком в `/web`**, без единой строки в `/proto` и
`/server`: `/admin/arenas` пересобирается из примитивов 0022/0023 по
правилам 0024–0026 (`PageHeader`, `TableHead`/`TableRow`, модалки вместо
раскрытых форм, тосты через `shared/lib/toast`, скелетоны), и получает
**живой статус строки**, вычисляемый чистой функцией из уже существующей
доски площадки (`GET /api/arenas/[id]/board`, спека 0013). Доска
запрашивается по одной на активную площадку через `useQueries` с
периодическим обновлением (решение пользователя 2026-08-13; альтернативы —
агрегирующая ручка BFF и агрегирующий RPC — отклонены, spec NFR-3).

Четыре содержательных сдвига помимо визуала:

1. **Экран настройки начинает показывать операционное состояние.** Доска
   площадки существует с 0013 и до сих пор читалась только на странице
   самой площадки; список площадок получает её как производную величину
   (spec FR-3), не приобретая при этом никаких прав на ведение боя.
2. **Живой канал табло сознательно не используется.** `WatchArenaBoard`
   (0015) регистрирует подписчика в комнате площадки и влияет на
   `scoreboardCount`/`thisOrdinal`/выбор авторитета таймера — список
   настроек, открытый в соседней вкладке, не должен менять поведение
   идущего боя (spec FR-9). Отсюда polling, а не SSE, — и это не
   компромисс производительности, а требование корректности.
3. **Дефолтная длительность боя переезжает к площадке.** Поле «Дефолт (с)»
   уходит из `features/arena-timer/ui/TimerControls.tsx` в модалку правки
   площадки (spec FR-12/FR-13); RPC `SetArenaDefaultDuration` и ручка
   `PUT /api/admin/arenas/[id]/default-duration` (0015) остаются те же,
   меняется только точка вызова.
4. **Единственная английская строка, которую BFF сочиняет сам,
   переводится.** Гейт «нельзя архивировать занятую площадку» (0011, FR-10)
   живёт в ручке архивации и её текст уходит прямо в интерфейс (spec п.6
   «Проблема»); строка переписывается по-русски в самой ручке — сопоставлять
   строки в UI было бы хрупко.

**Изменений нет.** Все данные и действия экрана уже есть в контракте:

| Что нужно экрану | Существующий RPC | Спека |
| --- | --- | --- |
| список площадок | `ArenaAdminService.ListArenas` | 0008 |
| создание/правка | `CreateArena` / `UpdateArena` | 0008 |
| архив/восстановление | `ArchiveArena` / `RestoreArena` | 0008 |
| порядок | `ReorderArenas` | 0008 |

`make generate` не требуется. Запись «Арены → новый API нужен? нет» в
`docs/design-sync.md` остаётся верной (в отличие от 0025/0026, где её
пришлось править).

## Server (модули и слои)

**Изменений нет.** Ни `modules/arena`, ни `modules/stage` не трогаются:
домен, сервис, репозиторий, миграции и api-слой остаются как есть. Гейт
занятости площадки сознательно живёт в BFF (композиция `stage` + `arena`,
иначе `arena → stage` замкнул бы цикл с `stage → arena`, спека 0011) и
таким и остаётся — меняется только текст его сообщения.

### `shared/`

Изменений не требуется — примитивы берутся как есть: `ui/{page-header,
table-head,table-row,dialog,checkbox,input,label,textarea,button,badge,tag,
empty-state,skeletons,tooltip}`, `lib/{toast,cn}`. Строка площадки
укладывается в существующее API `TableRow` (`state: "out"` для архивной,

контекста статуса, `node`-слот из 0025 — для составных ячеек: стрелок
порядка, индикатора состояния и группы действий).

### `entities/arena/`

- `lib/types.ts` — **без изменений** (`defaultDurationSeconds` там с 0015).
- `lib/format.ts` — **новый**: `formatDurationLabel(seconds)` → `«3:00»`
  (spec FR-1, колонка длительности и быстрые значения модалки). Отдельная
  чистая функция, а не копия локального форматтера из `TimerDisplay` — тот
  работает с сотыми секунды для таймера, здесь нужны секунды настройки.

### `entities/arena-live/`

- `lib/status.ts` — **новый чистый модуль** (без React, целиком под
  юнит-тесты) — ядро инкремента:
  ```ts
  export type ArenaLiveStatusKind =
    | "free" | "preparing" | "bout" | "between" | "finished" | "archived" | "unknown";

  export type ArenaLiveStatus = {
    kind: ArenaLiveStatusKind;
    title: string;        // «Идёт бой · Кравцов — Ильин»
    detail: string | null; // «Длинный меч · Пул A · бой 14 из 18 · 3:2»
    pulse: boolean;       // индикатор пульсирует только у идущего боя
  };

  export function arenaLiveStatus(board: BoutBoard | null): ArenaLiveStatus;
  ```
  Правила (spec FR-3): `board === null` либо `board.pool === null` → `free`;
  текущий бой `IN_PROGRESS` → `bout` (счёт в `detail`); все бои
  `FINISHED` → `finished`; ни один бой не начат → `preparing`; иначе →
  `between` (в `title` — следующая пара). `detail` собирается из
  `pool.nominationName`, `pool.name` и уже существующих `boutNumber(board)`
  / `nextBout(board)` из `lib/types.ts` — вторая реализация «какой бой по
  счёту» не заводится.
- Файл живёт в `arena-live`, а не в `arena`, потому что уже импортирует
  DTO `entities/pool` (тот же приём, что `lib/types.ts` этой сущности) и
  относится к горячим данным, а не к реквизитам площадки.

## События

Доменных событий инкремент **не издаёт и не потребляет**. Модуль `arena` не
event-sourced, живой статус читается синхронно существующим RPC. Живой
канал (`WatchArenaBoard`, SSE) сознательно не используется — см. «Обзор
решения», п. 2.

## Риски и открытые вопросы

- **N запросов доски за цикл.** Осознанный размен (spec NFR-3): на масштабе
  турнира площадок единицы. Запасной вариант, если на смоуке окажется
  тяжело, — увеличить интервал и/или запрашивать доски только при видимой
  вкладке (второе делаем сразу). Агрегирующая ручка BFF остаётся
  отклонённой альтернативой, а не забытой.
- **Соблазн переиспользовать `boutBoardKeys`.** Тот же URL, тот же ответ —
  но ключ принадлежит фиче ведения боя и инвалидируется её мутациями.
  Общий ключ дал бы скрытую связь двух экранов и внезапные перезапросы;
  держим отдельный ключ, дублирование признаём сознательным.
- **Правка чужого экрана.** Удаление поля дефолтной длительности из
  `TimerControls` — единственное касание страницы площадки, которую
  переделывает 0033. Ограничиваемся удалением поля и обновлением его теста,
  ничего больше в панели не трогаем. Спека 0033 ещё не написана (резерв ADR
  0015) — фиксируем здесь, чтобы при её написании дефолт длительности не
  сочли пропавшим: он переехал на экран площадок этим инкрементом.
- **Пульсация индикатора.** Анимация под `motion-safe:` и обязательная
  текстовая подпись (spec FR-4/NFR-4) — иначе состояние площадки
  оказывается доступно только зрячему пользователю без чувствительности к
  движению.
- **Гонка «архивировали занятую».** Между отрисовкой строки и нажатием
  «В архив» пул может встать на площадку: арбитр — сервер/BFF, экран лишь
  честно показывает отказ (spec FR-15). Предварительно скрывать действие по
  живому статусу **не** будем — это создало бы вторую, расходящуюся с
  сервером, копию правила.
- **Тост «Отменить» у архивации честен ровно потому, что архивация ничего
  не разрушает** (в отличие от 0026, где отмена не вернула бы посев).
  Если в будущем архивация получит побочные эффекты, FR-14 придётся
  пересмотреть — это фиксируется здесь, чтобы правило не унаследовали
  вслепую.
