## Обзор решения

Инкремент целиком в `/web`: ни `proto`, ни Go-сервер не меняются (NFR-1).
Экран `/admin` пересобирается из примитивов 0022/0023 — `TableHead`/`TableRow`
вместо двух `Card`-списков, `FilterChip` вместо отсутствовавших фильтров,
`Pagination`/`EmptyState`/`SkeletonRows`/`toast*` из 0023.

Три содержательных сдвига помимо визуала:

1. **Один источник данных вместо двух.** `ListUsers` уже возвращает *все*
   учётки (`SELECT ... FROM auth.users ORDER BY created_at`), включая
   админов, — значит второй запрос `ListAdmins` экрану не нужен вовсе:
   разбивка по ролям и счётчики чипов считаются из того же массива. Хук
   `useAdmins` после этого остаётся без потребителей и удаляется вместе с
   `listAdminsRequest` (BFF-ручка `/api/admin/admins` **остаётся** — это
   контрактная поверхность, а не мёртвый код экрана).
2. **`AppShell` расщепляется.** Спека 0022 завела в `shared/ui/app-shell.tsx`
   слоты `crumb/title/status/meta/secondary/action` «на вырост» и оставила их
   пустыми — но шапка рендерится в `app/(admin)/admin/layout.tsx`, а данные
   для слотов (счётчик учёток, кнопка, открывающая модалку) знает страница, и
   передать их снизу вверх в App Router нечем. Решение (spec FR-19):
   header-строка выносится в самостоятельный `shared/ui/page-header.tsx` с
   теми же слотами, `AppShell` остаётся только верхней полосой
   (`brand/nav/userSlot`), а страница рендерит `PageHeader` первым элементом —
   визуально это ровно тот же двухрядный макет.
3. **Смена роли получает обратную связь.** Тосты вызываются в `ui/`-слое
   (в колбэках `mutate`), а не внутри RQ-хуков: хуки остаются чистыми
   обёртками над fetcher'ами, как в остальных фичах, а знание о канале
   обратной связи (правило 0023) живёт там же, где UI.

## Контракты (proto)

**Изменений нет** (NFR-1). Используются как есть:

- `AdminService.ListUsers(limit, offset)` — единственный источник списка.
  Экран запрашивает весь список одним вызовом с явным большим `limit`
  (константа в `features/admin/api/requests.ts`, ~1000): постраничность
  клиентская (spec NFR-2), а дефолт BFF `limit=100` обрезал бы список молча.
- `AdminService.PromoteUser` / `DemoteUser` — действия строки; они же —
  взаимно обратные вызовы для «Отменить» (FR-11).
- `AdminService.CreateAdmin` — модалка создания.
- `AdminService.ListAdmins` — **экраном больше не используется** (см. «Обзор»,
  п.1).

## Server (модули и слои)

**Изменений нет.** Ни `modules/auth`, ни миграции, ни `internal/platform` не
трогаются. Проверки «нельзя понизить себя» и «нельзя понизить последнего
админа» уже живут в `modules/auth/service/admin.go` и остаются единственным
местом этих правил — клиент их не дублирует, а показывает текст отказа
(FR-12).

## Web (FSD + BFF)

### `shared/`

- `shared/ui/page-header.tsx` — **новый**. Переносит header-строку из
  `app-shell.tsx` без изменения разметки/классов: слоты
  `crumb/title/status/meta/secondary/action`, `meta` расширяется до
  `React.ReactNode` (счётчик приходит из данных, а не строкой). Правило

- `shared/ui/app-shell.tsx` — **сокращается** до `brand/nav/userSlot`;
  header-слоты и их условный рендер убираются, комментарий про «заполняются
  спеками 0024+» заменяется ссылкой на `PageHeader`.
- `shared/lib/datetime.ts` — **дополняется** двумя чистыми функциями:
  `formatRelativeDay(iso, now)` («сегодня» / «вчера» / «N дней назад» / далее
  «18 мар» / с прошлого года — «18 мар 2025») и `formatDateTime(iso)` (полная
  дата+время для подсказки). Обе — на существующем `parseIsoToDate`; `now`
  параметром, чтобы тесты не зависели от системного времени.
- `shared/lib/paginate.ts` — **дополняется** `pageSlice(items, page, size)`
  (чистая нарезка) и `clampPage(page, pageCount)`; `paginationWindow` уже есть.

### `features/admin/`

- `api/requests.ts` — `listUsersRequest(limit?)` шлёт `?limit=…`;
  `listAdminsRequest` и тип-ветка `"admins"` удаляются.
- `api/use-users.ts` — передаёт лимит; `api/use-admins.ts` — **удаляется**.
- `api/use-promote-user.ts` / `use-demote-user.ts` — без изменений (инвалидация
  списков уже есть); из `onSuccess` убирается только инвалидация
  `adminKeys.admins`, если ключ становится неиспользуемым — `keys.ts`
  сокращается до `users`.
- `lib/select-users.ts` — **новый, чистый модуль экрана** (без React, целиком
  под юнит-тесты):
  - `sortUsers(users)` — админы выше, внутри группы по имени/email (FR-3);
  - `filterUsers(users, { role, query })` — фильтр роли + подстрочный
    регистронезависимый поиск по имени и email (FR-5, FR-7);
  - `roleCounts(users)` — `{ admins, users, total }` по всему списку (FR-6);
  - `initials(user)` — инициалы для аватара (FR-4).
- `ui/users-screen.tsx` — **новый клиентский корень экрана**: держит состояние
  фильтра/поиска/страницы (`useState`, ADR 0006 — локальное UI-состояние),
  зовёт `useUsers`, рендерит `PageHeader` (крошка приходит пропом с сервера,
  `meta` — из данных), панель фильтров, таблицу и пагинацию, владеет модалкой
  создания.
- `ui/users-filters.tsx` — **новый**: три `FilterChip` (`dropdown={false}`,
  `tone="active"` у выбранного, `aria-pressed`) + поле поиска (`Input` с

- `ui/users-table.tsx` — **новый**: `TableHead` с четырьмя колонками +

  решение о том, расширять ли `TableRow` слотом `node` или верстать строку

- `ui/user-row.tsx` — **переписывается** под колонки FR-1 (инициалы, имя,

### Server components vs client

| Слой | Где | Почему |
| --- | --- | --- |
| `page.tsx` | server | cookie + gRPC (`getCurrentUser`, `getActiveTournament`) |
| `UsersScreen` и всё под ним | client | RQ, состояние фильтров, модалка, тосты |
| `PageHeader` | презентационный | рендерится внутри клиентского экрана (`meta` зависит от данных) |

### State

- server-state (список) → TanStack Query (`useUsers`), инвалидация после
  мутаций — как сейчас;
- UI-state (фильтр, поиск, страница, открытость модалки) → `useState` внутри
  `UsersScreen` (кросс-компонентного шаринга нет, Zustand не нужен);
- порядок/фильтрация/нарезка — чистые функции, не состояние.

## Риски и открытые вопросы

- **`TableRow` рассчитан на текстовые ячейки** (`cells: {text, sub, tags}`), а
  строке пользователя нужны аватар-инициалы и кнопка. Развилка на T-задаче:
  расширить примитив слотом `node` (пригодится всем экранам 0025+) либо
  сверстать строку экрана рядом, переиспользуя классы. Предпочтение —
  расширение примитива, если оно выходит аддитивным (существующее
  `cells`-API не ломается); иначе — второй вариант, чтобы не тащить
  общий примитив под один экран.
- **Удаление `/admin/create`** ломает сохранённые ссылки — принято осознанно
  (spec FR-17); проверить, что на роут нет ссылок ни из кода, ни из тестов
  (грепом на `admin/create` останется только BFF-ручка `/api/admin/create`).
- **Лимит выборки.** `limit≈1000` — не постраничность, а «загрузить всё для
  масштаба турнира» (NFR-2). Если счётчик учёток упирается в лимит, экран
  начнёт молча врать в `meta`; на T-задаче добавить защиту — при количестве
  ровно в лимит показывать «N+ учётных записей» или логировать. Настоящее
  решение (серверный поиск/постраничность) — отдельная фича с изменением
  контракта.
- **Крошка с названием турнира** добавляет каждому экрану серверный вызов
  `getActiveTournament()`. Здесь это один вызов на страницу и он уже
  устойчив к отсутствию турнира; если при 0025+ окажется, что вызов
  дублируется на каждом экране, его стоит поднять в `admin/layout.tsx` и
  прокидывать вниз — но не раньше, чем появится второй потребитель.
- **`AdminHeader` временно сосуществует с `PageHeader`**: остальные разделы
  админки продолжают использовать старый компонент до своих спек. Это
  ожидаемое переходное состояние, а не недоделка; удалить `admin-header.tsx`
  можно будет, когда на `PageHeader` переедет последний экран.
