> `[NEEDS CLARIFICATION]`.

- Статус: draft
- Дата: 2026-08-15
- Спека: `./spec.md`

## Обзор решения

Инкремент **целиком в `/web`**, без единой строки в `/proto` и `/server`:
единственный компонент `features/nomination-pools/ui/nomination-pools.tsx`
(и его `api/`-слой) пересобирается по правилам 0022/0023/0024–0029
(тосты через `shared/lib/toast`, `Skeleton`, детерминированные пустые
состояния), не трогая ни страницу-хозяина
(`app/(admin)/admin/nominations/[id]/stages/[stageId]/page.tsx`, спека
0032), ни `entities/bout`/`entities/pool` типы, кроме одной новой чистой
функции.

Три содержательных сдвига, не сводящихся к перекраске:

1. **Семь мутаций получают обратную связь по правилу 0023** вместо одного
   постоянного `Alert`-баннера на все сразу (`mutationError` убирается
   целиком). Три хука (создание пула, автораспределение, DnD) сегодня не
   вызывают тост вовсе даже при успехе — становится `toastSuccess`/
   `toastUndo`/тихий успех по FR спеки (см. таблицу ниже).
2. **Удаление пула и автораспределение начинают предлагать «Отменить» в
   тосте**, используя тот же undo-слот, что уже отдаёт `useUndo` кнопке
   тулбара (0009, FR-7a) — без новой мутации, без модалки (решение
   пользователя 2026-08-15, spec «Решения по открытым вопросам»).
3. **Ошибки сервера переводятся на русский по HTTP-статусу**, а не
   показываются как есть (`err.rawMessage` от Go-домена модуля `pool`,
   сейчас пробрасывается без перевода) — тот же приём, что в 0028/0029:
   статус, не сопоставление строк (Go-текст ошибки волатилен и не наш код,
   в отличие от 0027, где строку можно было переписать прямо в BFF).

## Контракты (proto)

**Изменений нет.** Все данные и действия экрана уже есть в контракте
(`PoolAdminService`/`StageAdminService`, спеки 0009/0011/0018): создание/
удаление пула, `assign`/`unassign`, автораспределение, undo, смена статуса
раскладки. `make generate` не требуется. Запись «Посев — группы → новый API
не нужен» в `docs/design-sync.md` остаётся верной.

## Server (модули и слои)

**Изменений нет.** `modules/pool` (и `modules/stage`, `modules/bout`) не
трогаются — ни домен, ни сервис, ни репозиторий, ни api-слой, ни миграции.

## Web (FSD + BFF)

### BFF (Route Handlers)

- `app/api/stages/[stageId]/{pools,reset,assign,unassign,distribute,undo,
  status}/route.ts`, `app/api/pools/[poolId]/route.ts` — **без изменений**
  в логике; `errorResponse` (`lib/grpc/errors.ts`) уже мапит
  `connect.Code` → HTTP-статус (`FailedPrecondition`/`Aborted` → 409,
  `InvalidArgument` → 400 и т.д.), этого достаточно для перевода на клиенте
  по статусу (обзор, п.3) — сама ручка `errors.ts` не меняется, она уже
  общая для всего BFF.

### `entities/pool/lib/types.ts`

- Новая чистая функция **`poolLayoutCounts(layout: PoolLayout): {
  assigned: number; total: number; poolCount: number }`** (spec FR-1):
  `poolCount = layout.pools.length`, `total = layout.unassigned.length +
  Σ pool.members.length`, `assigned = total − layout.unassigned.length`.
  Не метод раскладки на сервере — сервер эту сводку не отдаёт и не должен
  (NFR-1), считается на клиенте из уже загруженных данных.

### `features/nomination-pools/api/`

- **`requests.ts`** — единая внутренняя `fetchLayout(url, init)` (уже
  общая для всех восьми запросов раскладки — создание/удаление/DnD/авто/
  undo/статус/чтение) кладёт **`status: res.status`** рядом с `error` в
  ошибочной ветке. Тип результата (`PoolLayoutResult`) получает
  необязательное поле `status?: number`. Успешная ветка и `fetchBouts` не
  меняются.
- **`errors.ts`** — новый: **`poolsErrorMessage(_error: string, status?:
  number): string`** — по образцу `presetErrorMessage` (0029,
  `features/format-presets/api/errors.ts`): сигнатура сохраняет параметр
  ошибки для симметрии с сестринскими модулями, но перевод строится
  **только по статусу** — Go-текст `pool`-домена волатилен, сопоставлять
  строки нельзя (тот же мотив, что `presetErrorMessage`/0028). Большинство
  мутаций здесь — `FailedPrecondition` (→ 409) по разным причинам
  (раскладка `ready`, нет пулов для авто, нет истории для undo, есть
  проведённые бои при возврате в `draft`, 0013) — без нового proto-поля
  различить их надёжно нельзя, поэтому один общий текст:
  - `409` → «Действие недоступно: раскладка зафиксирована либо изменять
    уже нечего»;
  - `400` → «Некорректный запрос»;
  - `401`/`403` → «Недостаточно прав»;
  - иначе (в т.ч. `undefined`) → «Не удалось выполнить действие,
    попробуйте ещё раз».
- **`use-create-pool.ts`** — `mutationFn` при отказе бросает
  `new Error(poolsErrorMessage(res.error, res.status))` (перевод — сразу
  внутри `mutationFn`, как `use-delete-preset.ts` в 0029 — `onError`/
  компонент видят уже русский `err.message`, без доп. полей на `Error`).
  `onSuccess` → `toastSuccess("Пул создан")` (spec FR-3); `onError` →
  `toastError(err.message)` без `retry`.
- **`use-delete-pool.ts`** — тот же перевод ошибки внутри `mutationFn`.
  Toast — не в хуке: хук не знает про `undo`-хук (циклическая зависимость
  между хуками нежелательна), связка делается в `nomination-pools.tsx`
  (spec FR-4): `deletePool.mutate(id, { onSuccess: () =>
  toastUndo("Пул удалён", { onUndo: () => undo.mutate() }), onError: (e)
  => toastError(e.message) })`.
- **`use-auto-distribute.ts`** — перевод ошибки внутри `mutationFn`; тост —
  из компонента (spec FR-5): `autoDistribute.mutate(undefined, {
  onSuccess: () => toastUndo("Раскладка обновлена", { onUndo: () =>
  undo.mutate() }), onError: (e) => toastError(e.message) })`.
- **`use-undo.ts`** — перевод ошибки внутри `mutationFn`; `onSuccess` — без
  тоста (spec FR-7, результат виден по раскладке); `onError` →
  `toastError(err.message)` без retry — вызывается из компонента (тот же
  хук уже используется и кнопкой тулбара, и как цель `onUndo` из тостов
  FR-4/FR-5, поэтому тост на его собственную ошибку логичнее держать там
  же, где остальные обработчики этого экрана).
- **`use-set-layout-status.ts`** — перевод ошибки внутри `mutationFn`;
  `onSuccess` → `toastSuccess` с текстом по направлению перехода
  («Раскладка зафиксирована» / «Раскладка возвращена в черновик», spec
  FR-8 — направление известно хуку по аргументу `status: "draft"|"ready"`);
  `onError` → `toastError(err.message)` без retry (покрывает и случай 0013
  «есть проведённые бои» — под общим текстом `poolsErrorMessage(409)`, см.
  «Риски»).
- **`use-reset-layout.ts`** — **без изменений** (уже `toastUndo` +
  `ConfirmDialog`, spec FR-6; текст ошибки при желании можно тоже перевести
  через `poolsErrorMessage`, но это не требование спеки — не трогаем, раз
  работает).
- **`use-assign-fighter.ts` / `use-unassign-fighter.ts`** — перевод ошибки
  внутри `mutationFn`; `onError` уже откатывает optimistic-обновление —
  добавляется `toastError(err.message)` без retry, вызывается из
  компонента (`assign.mutate({...}, { onError: (e) =>
  toastError(e.message) })`) рядом с существующей optimistic-логикой
  хука — успех по-прежнему без тоста (spec FR-9).

### `features/nomination-pools/ui/nomination-pools.tsx`

- **`Toolbar`** переписывается:
  - принимает `counts = poolLayoutCounts(layout)`, рендерит «N / M
    распределено · K пул(а/ов)» рядом со статусом (spec FR-1; склонение
    «пул/пула/пулов» — локальная функция по образцу `presetsCountWord`
    из `preset-library.tsx`, 0029, не общий `shared/lib`: единственный
    потребитель);
  - статус раскладки — `<Badge tone={readOnly ? "success" : "warn"}>`
    (существующие тона 0022, `badge.tsx`) вместо
    `variant={readOnly ? "default" : "secondary"}` — даёт зелёный/янтарный
    цвет как в моке без нового компонента;
  - подписи кнопок: «Добавить группу» → **«+ Пул»**, «Распределить по
    группам» → **«Распределить автоматически»**, «Зафиксировать
    раскладку» → **«Зафиксировать»** (spec FR-2); «Сбросить раскладку» и
    «Отменить» — без изменений.
- **Постоянный `Alert` (`mutationError`) удаляется целиком** вместе с
  агрегацией шести `.error?.message` (spec FR-10) — импорт `Alert`/
  `AlertDescription` остаётся только для состояния ошибки первичной
  загрузки (см. ниже).
- **Загрузка (`isLoading`)** — вместо `<p>Загрузка…</p>`: локальный блок
  скелетонов той же формы, что реальная раскладка (280px-колонка + сетка
  карточек), собранный из `Skeleton` (0022) — не общий `SkeletonRows`/
  `SkeletonCards` (они не знают про асимметричную двухколоночную форму
  этого экрана), а маленький локальный компонент
  `NominationPoolsSkeleton` в том же файле (spec FR-11).
- **Ошибка загрузки (`error`)** — сообщение + кнопка «Повторить», вызывающая
  `refetch()` из `useLayout` (`useQuery`, `refetch` уже доступен — как в
  `preset-library.tsx`, 0029), вместо статичного `Alert` (spec FR-12).
- **`UnassignedColumn`** — пустое состояние: подпись **«Пусто»** (без
  изменений).
- **`PoolColumn`**:
  - пустое состояние меняется на **«Перетащите бойца сюда»** (spec FR-13);
  - кнопка удаления вызывает `deletePool.mutate` **сразу**, без открытия
    `ConfirmDialog` (spec FR-4, «Вне скоупа» решения); иконка/`aria-label`
    — без изменений.
- **`ConfirmDialog` сброса раскладки (`confirmResetOpen`)** — без
  изменений (spec FR-6).
- Токены карточек бойцов/пулов, отступы, скругления — точечно
  подгоняются под 0022 (`bg-card`/`border` уже используют переменные темы,
  правки — косметические, не меняют структуру компонентов).

### Server components vs client

Без изменений: `NominationPools` остаётся клиентским компонентом
(`"use client"`) — DnD, RQ-мутации, тосты.

### State

Без изменений в стратегии (ADR 0006): server-state — TanStack Query
(`useLayout` + семь мутаций), локальный UI-state (`draggingFighter`,
`confirmResetOpen`) — `useState`. Новых Zustand-сторов не заводится.

## Риски и открытые вопросы

- **`poolsErrorMessage` — один общий текст на все причины `409`.** Модуль
  `pool` возвращает `FailedPrecondition` по нескольким разным причинам
  (раскладка `ready`, нет пулов для автораспределения, нет истории для
  undo, есть проведённые бои при возврате в `draft` — 0013), а без нового
  proto-поля клиент не может отличить их надёжно иначе, чем
  сопоставлением волатильного `rawMessage` (отклонено по прецеденту 0028).
  Общая формулировка «раскладка зафиксирована либо изменять нечего» не
  называет точную причину — принятый компромисс NFR-1 (без правки
  сервера). Если в ручном смоуке общая фраза окажется непонятной для
  конкретного частого случая (например, «нет проведённых боёв» при
  жалобах пользователей) — точечное уточнение per-действие обсуждается
  отдельно, не блокирует этот инкремент.
- **`toastUndo` дублирует персистентную кнопку «Отменить» в тулбаре** для
  удаления пула и автораспределения (по явному решению пользователя,
  2026-08-15) — та же схема уже работает для сброса раскладки, регрессии
  не создаёт, но означает, что после успешной мутации на экране одновременно
  два способа вызвать один и тот же `undo.mutate` (транзиентная кнопка в
  тосте + постоянная в тулбаре). Осознанно, не переигрывается.
- **Разделение экрана и страницы-хозяина.** `NominationPools` не заводит
  `PageHeader` (см. spec «Вне скоупа») — до правки 0032
  (`stages/[stageId]/page.tsx`) экран продолжает жить под старым
  `AdminHeader`, в узкой колонке `max-w-6xl`. Это осознанный
  промежуточный вид (как было и в предыдущих экранных спеках между их
  собственной готовностью и переездом соседних частей), не баг этого
  инкремента.
