# Spec: Выгрузка отдельных боёв номинации

> Артефакт SDD (ADR 0008). ЧТО и ЗАЧЕМ. Источник: аудит M12/F07.

- Статус: draft
- Дата: 2026-09-25
- Решение до реализации: D-EXPORT

## Проблема

Существующая выгрузка итоговых мест не позволяет проверить результаты отдельных
боёв вне приложения. Организатору нужен файл с парами, этапами, статусами и
результатами, который можно сверить с экраном номинации.

## Акторы

- **admin** — выгружает бои выбранной номинации для сверки и передачи организаторам.
- **user / гость** — новая административная выгрузка недоступна.

## Пользовательские сценарии

1. Скачать все существующие бои одной номинации, включая незавершённые,
   открыть файл в табличном редакторе и найти бой по устойчивому ID.
2. Отличить группу от половины плейоффа, текущий счёт от окончательного
   результата и технический исход от обычного, когда технические исходы внедрены.
3. Повторить выгрузку после исправления результата и получить актуальное состояние.

## Требования

Ниже — **предложение D-EXPORT**, а не утверждённый формат.

- FR-1: Экспорт доступен admin из экрана схемы номинации. Файл — CSV всех
  существующих боёв этой номинации, без фильтра по экранной странице, этапу
  или состоянию. Итоговый протокол мест остаётся отдельным действием.
- FR-2: Одна строка соответствует одному реальному бою. Включаются группы,
  верхние/нижние половины плейоффа, финал и бой за третье место. Ожидающая
  пара без созданного боя и автоматический проход без боя отдельными
  строками не становятся. Удалённые при сбросе бои не восстанавливаются.
- FR-3: Строка содержит ID номинации/этапа/пула/боя; названия номинации, этапа
  и пула; тип и порядок этапа, номер пула, тур и номер боя внутри пула;
  ID, имена, клубы обоих бойцов; состояние, счёт обоих, исход, тип результата
  и причину технического результата при её наличии.
- FR-4: Имена и клубы соответствуют сохранённому представлению участников
  боя; экспорт не подставляет актуальные имена из отдельно изменённой карточки.
- FR-5: У незавершённого боя исход, тип результата и причина пустые. Счёт
  показывает текущее значение, включая 0:0; состояние явно отличает такой
  бой от завершённой ничьей. Сброшенный/переоткрытый бой выгружается в текущем
  состоянии без старого победителя.
- FR-6: Для законченного обычного боя исход — сторона A, сторона B либо ничья.
  Когда реализованы технические исходы, результат берётся из их доменной
  модели; победитель не угадывается сравнением очков. Нейтральный/без победителя
  результат обозначается явно согласно принятому правилу технических исходов.
- FR-7: Порядок строк устойчив при неизменных данных: порядок этапа, номер
  пула, порядок боя, ID как последнее разрешение равенства. Заголовки и порядок
  колонок фиксированы. Названия с кавычками, запятыми, переносами и кириллицей
  читаются корректно; текст не исполняется как формула табличного редактора.
- FR-8: Номинация без боёв даёт файл только с заголовком; отсутствующая
  номинация — понятную ошибку, а не пустой успешный файл.
- NFR-1: Новая выгрузка защищена на сервере, а не только скрытой кнопкой.
  Данные учёток, контакты и авторы изменений в неё не входят.
- NFR-2: Экспорт — текущее чтение, а не архив и не подписанный протокол.
  Он не меняет состав, результаты, раскладку, события или состояние боя.

## Критерии приёмки

- **AC-1** Given номинация с группами и плейоффом, финалом и третьим местом;
  When admin экспортирует; Then каждый созданный бой присутствует ровно один
  раз, этап/пул/пара/счёт соответствуют системе, данные другой номинации отсутствуют.
- **AC-2** Given not started 0:0, in progress 2:1 и finished draw 2:2;
  When экспортировать; Then состояния различимы, первые два не имеют итогового
  исхода, третья строка содержит ничью и обычный тип результата.
- **AC-3** Given bye и ещё не созданная пара будущего раунда; When экспортировать;
  Then фиктивных боёв нет. Given номинация без боёв; Then заголовок без строк.
- **AC-4** Given имя/клуб с кириллицей, кавычкой, запятой, переносом или началом
  `=`, `+`, `-`, `@`; When открыть файл; Then колонки не сдвинуты и текстовые
  значения не интерпретируются как формулы.
- **AC-5** Given неизменные данные; When выгрузить дважды; Then строки и колонки
  совпадают. Given изменённую карточку бойца; Then представление старого боя
  остаётся соответствующим его сохранённым данным.
- **AC-6** Given завершённый бой; When его переоткрыть/сбросить и экспортировать;
  Then старый исход отсутствует, текущее состояние/счёт корректны.
- **AC-7** Given user или гостя; When вызвать endpoint/RPC напрямую;
  Then отказ без файла. Given неизвестную номинацию; Then ошибка not found.
- **AC-8** Given технический результат после реализации 0056; When экспортировать;
  Then тип/причина/исход соответствуют ему даже при счёте, не определяющем
  победителя. Этот AC обязателен для совместной приёмки 0056+0059, но не требует
  реализовывать технические результаты внутри 0059.

## Вне скоупа

- Журнал сходов, последовательность событий, личные данные и история коррекций.
- Экспорт всего турнира, XLSX/PDF, настраиваемые колонки, фоновые задания.
- Новый модуль отчётности, постоянное хранилище экспортов, аудит скачиваний.
- Вычисление новых правил исходов, рейтинга, продвижения, замены или цен.
- Неизменяемый архив состояния турнира; гарантированный единый момент снимка
  всех модулей при параллельном редактировании.
