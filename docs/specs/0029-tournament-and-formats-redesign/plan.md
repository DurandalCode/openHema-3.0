- Статус: ready

- Спека: `./spec.md`

## Обзор решения

Инкремент **целиком в `/web`**, без единой строки в `/proto` и `/server`: оба
экрана пересобираются из примитивов 0022/0023 по правилам 0024–0028
(`PageHeader`, модалки вместо инлайн-правки, тосты через `shared/lib/toast`,
`ConfirmDialog` на необратимое, `EmptyState`, скелетоны).

Три содержательных сдвига помимо визуала:

1. **Блок турнира становится общим и оживает.** `TournamentHero` переезжает
   из `widgets/tournament-hero/` в `entities/tournament/ui/tournament-hero.tsx`
   (решение пользователя, spec FR-3). Это **вынужденный** переезд, а не
   вкусовой: превью живёт внутри `features/tournament-settings/`, а
   `features → widgets` запрещён FSD (`web/AGENTS.md`, п.6) — из `entities`
   же блок законно видят и `app/page.tsx`, и фича. Сам блок при этом
   **не редизайнится** (его редизайн — 0034), меняется только адрес.
2. **Форма превращается в черновик с диффом.** Экран держит `draft` рядом с
   `saved`-снапшотом; отличия, валидация и сборка объекта для превью — три
   чистые функции в `entities/tournament/lib/draft.ts`, тестируемые без
   рендера (приём `registration-gate.ts` из 0028 и `entities/arena/lib/
   format.ts` из 0027).
3. **Отказы сервера переводятся по HTTP-статусу, а не по тексту** (приём
   0028): и `tournament: invalid input` из Go-домена, и конфликт имени
   пресета приходят английскими строками, которые нельзя переписать в
   ручке без правки сервера (NFR-1).

Два экрана **дизъюнктны по файлам** — отсюда два параллельных трека в
`tasks.md`.

### Server components vs client

| Слой | Где | Почему |
| --- | --- | --- |
| обе `page.tsx` | server | cookie + gRPC (`getActiveTournament`) / просто оболочка |
| `TournamentScreen` и всё под ним | client | draft-состояние, мутация, тосты |
| `PresetLibrary` и всё под ним | client | RQ + модалки + тосты (как сейчас) |
| `TournamentHero` | презентационный | без хуков и server-only импортов — потому и рендерится и на сервере (главная), и на клиенте (превью) |

### State

- server-state (активный турнир, список пресетов) → TanStack Query:
  существующие `useActiveTournament` / `usePresets` + мутации;
- **`draft` профиля турнира** → `useState` в `TournamentScreen`. В RQ его
  класть нельзя (это несохранённый ввод, а не серверное состояние), в
  Zustand — не за чем: состояние не переживает экран и не шарится между
  ветками дерева (ADR 0006);
- `saved`-снапшот → `useState`, инициализируется из пропа server component'а
  и заменяется ответом мутации (spec FR-9);
- UI-state (открытые модалки, id переименовываемого/удаляемого пресета) →
  `useState`;
- список изменённого, валидация, объект превью, счётчик пресетов, порядок
  карточек — **чистые функции**, не состояние.

## Риски и открытые вопросы

- **Переезд `TournamentHero` трогает файл, запланированный к редизайну в
  0034.** Осознанный размен (spec, решение п.3): без общего блока превью и
  главная разойдутся, а расхождение хуже отсутствия превью. Митигация —
  внешний вид блока в этом инкременте **не меняется вовсе**; 0034 получает
  тот же компонент по новому пути. Строка «Публичная главная v2» в
  `docs/design-sync.md` правится сразу, чтобы 0034 не искала виджет по
  старому адресу.
- **`entities/tournament/ui/` — первый `ui/`-подслой у этой сущности.**
  Прецедент в репозитории есть (`entities/user/ui/`), так что новой
  конвенции не заводим.
- **Дифф черновика может «дребезжать» на датах.** Сравнение идёт по
  ISO-строкам, а `DateTimeField` отдаёт ISO с секундами/миллисекундами от
  `Date`; ре-парсинг того же значения обязан давать ту же строку, иначе
  полоса изменений загорится сама собой. Проверяется тестом «идентичный
  черновик → пустой список» (AC-5) — если всплывёт, нормализуем обе стороны
  через `parseIsoToDate` перед сравнением.
- **Действия «Сохранить»/«Отменить правки» — только в шапке раздела.**
  Макет дублирует их ещё и под редактором; дубль не переносится: шапка —
  канон 0024 (FR-19), а вторая пара кнопок на экране означала бы два места,
  которые нужно держать в одинаковом disabled-состоянии. Если при ручном
  смоуке окажется, что до шапки далеко скроллить (длинный список
  контактов), — вернуть дубль дешевле, чем убрать, поэтому решение принято
  в эту сторону.
- **Превью считает `draftToTournament` на каждый ввод.** Это сборка объекта
  из десятка полей и рендер одного блока — стоимость незаметна (spec
  NFR-3); мемоизацию заранее не вводим, чтобы не усложнять то, что и так
  дёшево.
- **Русский текст отказа сохранения по статусу, а не по причине.** 400 от
  сервера может означать и пустое название, и битый диапазон дат — оба
  случая клиент ловит до отправки (FR-11/FR-12), поэтому в реальности до
  тоста доходят только неожиданные 400. Формулировка сознательно
  перечисляет обе причины; типизированный код ошибки потребовал бы `/proto`
  и противоречит NFR-1 (то же решение, что в 0028).
- **Уход со страницы с несохранёнными правками ничем не защищён** (spec
  «Вне скоупа»). После этого инкремента риск становится **заметнее**, а не
  больше: раньше несохранённые правки тоже терялись, но об их существовании
  ничто не сообщало. Если понадобится — это сквозной паттерн уровня 0023, а
  не правка одного экрана.
