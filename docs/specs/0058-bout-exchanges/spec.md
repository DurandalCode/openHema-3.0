# Spec: Журнал сходов боя

- Статус: draft; решение D-EXCH ещё не утверждено.
- Дата: 2026-09-25
- Источник: M22/F06 [аудита](../../feedback-audit-2026-09-25.md).

## Проблема и акторы

Секретарь хочет записывать каждое судейское решение как одну пару значений с отметкой времени, видеть историю и исправлять ошибку без потери следа. Текущий абсолютный счёт не объясняет, из каких сходов он получился.

## Предложение на согласование

- FR-1. Один сход — две **целочисленные дельты** счёта (в том числе отрицательные для санкций), необязательное пояснение и снимок оставшегося времени с точностью отображаемых сотых. Обе стороны записываются одним действием; свободный ввод остаётся, одних кнопок +1 недостаточно. Нулевая пара допустима для безрезультатного схода.
- FR-2. Суммарный счёт каждой стороны не может стать отрицательным. Показанный итог равен исходному счёту до начала журнала плюс действующие дельты, включая явно обозначенные коррекции.
- FR-3. Исправление/отмена схода сохраняет исходную запись, автора, время и причину; действующий список помечает исправленные и отменённые записи. Если правка раннего схода делает последующий промежуточный счёт отрицательным, она отклоняется с объяснением.
- FR-4. Завершённый бой редактируется только через существующее переоткрытие с проверкой зависимых результатов. Новый сход нельзя добавить в следующий бой из старой панели. Повтор отправки не добавляет запись повторно.
- FR-5. Снимок времени — значение, видимое на панели при записи, не доказательство точности официального секундомера. Если значение неизвестно, показывается «время не зафиксировано», а не 00:00. Время можно явно исправить с причиной; история сохраняется.
- FR-6. Существующие бои не превращаются в вымышленные сходы. Исторические изменения абсолютного счёта показываются как коррекции/начальный счёт; граница перехода обозначена. Кнопки счёта после включения журнала создают записи в той же истории.
- FR-7. При потере связи ввод сохраняется локально как неподтверждённый черновик, итог сервера не меняется. После возврата связи требуется подтверждение актуального боя/версии; автоматического слияния конфликтующих судейских решений нет.
- FR-8. Для первой версии полный журнал и пояснения доступны секретарю/администратору; зритель видит итог и обычное оглашение 0052. Публичный журнал и экспорт сходов — отдельное расширение 0059, не часть базового CSV боёв.

## Приёмка

- AC-1. Given итог 3:2, When записан сход +2:+1, Then одна запись и итог 5:3; сбой не сохраняет одну сторону отдельно.
- AC-2. Given повтор одного подтверждённого запроса, When retry, Then число сходов/счёт неизменны.
- AC-3. Given несколько сходов, When ранняя запись исправлена/отменена, Then последующие итоги пересчитаны, исходная запись доступна; недопустимый промежуточный минус блокируется.
- AC-4. Given сменившийся бой/версия, When старая панель отправляет запись, Then conflict и ни одной записи в новом бою.
- AC-5. Given журнал начат после счёта 4:3 старым способом, When открыта история, Then нет вымышленных сходов, есть обозначенный начальный счёт.
- AC-6. Given разрыв связи и затем новый current bout, When связь восстановлена, Then неподтверждённый ввод не отправляется автоматически другому бою.
- AC-7. Given нулевой сход и неизвестное время, When запись сохранена, Then 0:0 существует в журнале с пустой отметкой времени, не с фиктивным временем.
