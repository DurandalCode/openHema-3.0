# Spec: Импорт бойцов из файла

> Артефакт SDD (ADR 0008). Описывает **ЧТО и ЗАЧЕМ**. Без технологий, API и
> схем БД — только предметная область. Реализация — в `plan.md`.

- Статус: done
- Дата: 2026-09-17

## Проблема

Ростер турнира (спека 0007, экран из 0026) сейчас наполняется двумя путями:
электронной заявкой участника (0008/0025) и ручным заведением бойца admin'ом
по одному — диалог «Создать бойца»: имя, клуб, галочки номинаций.

Реальный организатор получает состав не только через форму на сайте. Клубы
присылают заявки списком (таблица, гугл-форма, письмо), часть турниров
регистрируется вообще вне платформы, а прошлогодний состав живёт в
выгрузке из старой системы. Для турнира на 100–300 участников с 3–8
номинациями ручное заведение — это несколько часов однообразного ввода,
в котором неизбежны опечатки в именах и названиях клубов; опечатка в клубе
ломает автораспределение по пулам с минимумом одноклубников (0009), а
опечатка в имени рождает дубль, который потом приходится сводить
`MergeFighters` (0040).

Нужен массовый ввод: admin загружает файл со списком участников, видит,
что система в нём разобрала, и одним подтверждением заводит весь ростер.

## Акторы

- **admin** (секретарь турнира) — готовит файл, загружает его, разбирает
  предпросмотр, подтверждает импорт, правит отклонённые строки и повторяет.
- **user** — не участвует: фича целиком внутри админского контура, на
  публичные экраны влияет только результатом (появившиеся бойцы в составе
  номинации).

## Пользовательские сценарии

1. Как **admin**, я хочу скачать образец файла, чтобы не гадать, какие
   колонки нужны и как записывать номинации.
2. Как **admin**, я хочу загрузить файл со списком участников и **до** записи
   в турнир увидеть, что именно будет создано: сколько новых бойцов, кто
   попадёт в какие номинации, какие строки система не поняла и почему.
3. Как **admin**, я хочу, чтобы бойцы из файла сразу оказались в нужных
   номинациях, а не заводились «голыми» с последующим ручным распределением.
4. Как **admin**, я хочу видеть строки, которые совпадают с уже заведёнными
   бойцами (тот же человек пришёл и заявкой, и в списке от клуба), и не
   получить в ростере дубль.
5. Как **admin**, я хочу, чтобы несколько кривых строк не отменяли импорт
   целиком: остальное должно загрузиться, а по проблемным строкам я хочу
   получить внятный список «строка N — причина», чтобы поправить файл и
   догрузить их.
6. Как **admin**, я хочу загружать файл повторно (клуб прислал уточнённый
   список), не боясь, что уже заведённые бойцы задвоятся.

## Требования

- FR-1: Система должна принимать от admin файл со списком участников
  турнира и разбирать его в набор строк «боец + номинации».
- FR-2: Импорт должен быть двухшаговым: сначала **разбор с предпросмотром**
  (ничего не записано), затем явное **подтверждение** admin'ом.
- FR-3: Предпросмотр должен показывать по каждой строке файла её исход:
  «новый боец», «дополнение существующего» (добавляются только новые
  участия), «пропуск» (полный дубль — ничего не меняется), «ошибка» с
  причиной.
- FR-4: Предпросмотр должен показывать сводку: сколько строк прочитано,
  сколько будет создано, дополнено, пропущено, отклонено.
- FR-5: Система должна распознавать номинации, указанные в файле, по их
  названию в текущем турнире (без учёта регистра и окружающих пробелов);
  нераспознанное название — ошибка строки, номинации по файлу **не
  создаются**.
- FR-5a: admin может выбрать номинации «по умолчанию» на всю загрузку; они
  применяются к строкам, где колонка номинаций пуста. Непустая колонка в
  строке всегда важнее умолчания (решение пользователя 2026-09-17: типовой
  список от клуба идёт без колонки, разнородная таблица — с колонкой, и
  один файл может содержать оба вида строк).
- FR-5b: Строка без номинаций (пустая колонка и пустое умолчание) законна:
  боец заводится без участий, как при ручном создании с пустым списком
  номинаций (0007). Ошибкой это не считается, но в предпросмотре видно.
- FR-6: Строка без имени бойца отклоняется. Клуб — необязателен (боец без
  клуба законен, см. `include_no_club` в 0041).
- FR-7: Дубль внутри самого файла (две строки про одного человека) должен
  схлопываться в одного бойца с объединением номинаций, а не в двух бойцов.
- FR-8: Совпадение строки с уже существующим бойцом турнира определяется
  по паре «имя + клуб» без учёта регистра и лишних пробелов (решение
  пользователя 2026-09-17: полные тёзки из разных клубов — разные люди;
  тёзки внутри одного клуба редки, а увиденный в предпросмотре случай
  admin разводит вручную). Совпавшая строка не создаёт нового бойца, а
  добавляет ему недостающие участия.
- FR-8a: Совпадение с **выведенным** с турнира бойцом (`withdrawn`) не
  применяется молча: строка отклоняется с причиной «боец выведен с
  турнира». Импорт не возвращает бойцов в турнир — это отдельное решение
  admin'а (`ReturnFighter`, 0007).
- FR-8b: Записи, слитые как дубли (`merged`, 0040), в сопоставлении не
  участвуют: строка сопоставляется с итоговой записью слияния.
- FR-9: Подтверждённый импорт записывает все корректные строки и отдельно
  возвращает список отклонённых с номером строки и причиной; отклонённые
  строки не блокируют остальные (решение пользователя 2026-09-17: одна
  опечатка не должна отменять две сотни корректных строк — секретарь
  правит по отчёту и догружает файл повторно, что безопасно за счёт
  FR-8/AC-8).
- FR-10: Отчёт об импорте (что создано/дополнено/пропущено/отклонено)
  показывается admin'у после подтверждения.
- FR-11: Система должна отдавать admin'у образец файла с ожидаемыми
  колонками и примером заполнения.
- FR-11a: Номер строки в отчёте — это номер строки **в файле, как его видит
  admin в редакторе** (с учётом строки заголовка), иначе отчёт нельзя
  приложить к файлу.
- FR-12: Импорт доступен только роли `admin` (как весь `FighterAdminService`).
- FR-13: Импортированный боец неотличим от заведённого вручную по своим
  правам и жизненному циклу: его можно править, выводить, снимать с
  номинаций и сводить `MergeFighters` теми же средствами (0007/0040).

- NFR-1: Файл ограничен по размеру и числу строк; превышение — понятная
  ошибка, а не таймаут. Ориентир рабочего объёма — до 1000 строк.
- NFR-2: Импорт не должен зависеть от того, как секретарь сохранил файл:
  принимаются и книга Excel, и CSV (решение пользователя 2026-09-17 —
  секретарь живёт в Excel/Google Sheets, а выгрузки из старых систем и
  гугл-форм приходят в CSV, так что нужны оба). Типовая выгрузка из Excel
  в русской локали читается без превращения имён в «крякозябры».
- NFR-3: Файл — транспорт, а не документ турнира: он разбирается и
  забывается, в объектное хранилище (ADR 0019) не кладётся.
- NFR-4: Подтверждённый импорт атомарен относительно самого себя: повторное
  нажатие «Импортировать» не должно задваивать ростер.

## Критерии приёмки

- **AC-1** (счастливый путь)
  - Given: турнир с номинациями «Лонгсворд» и «Сабля», пустой ростер
  - When: admin загружает файл с тремя строками, где у двух указана
    «Лонгсворд», у третьей — «Лонгсворд, Сабля», и подтверждает импорт
  - Then: в ростере три активных бойца, в составе «Лонгсворд» — три,
    в составе «Сабля» — один

- **AC-2** (предпросмотр ничего не пишет)
  - Given: тот же файл
  - When: admin загрузил файл и получил предпросмотр, но не подтвердил
  - Then: ростер турнира не изменился

- **AC-3** (неизвестная номинация)
  - Given: турнир без номинации «Копьё»
  - When: в файле строка с номинацией «Копьё»
  - Then: строка помечена ошибкой «неизвестная номинация: Копьё»,
    номинация не создаётся, остальные строки импортируются

- **AC-4** (пустое имя)
  - Given: файл, где во второй строке имя пустое
  - When: admin импортирует файл
  - Then: строка 2 отклонена с причиной «пустое имя», остальные записаны

- **AC-5** (дубль существующего бойца)
  - Given: в турнире уже есть боец «Иванов Иван» / клуб «Сталь» с участием
    в «Лонгсворде»
  - When: в файле строка «иванов иван; сталь; Лонгсворд, Сабля»
  - Then: новый боец не создан, у существующего появляется участие в
    «Сабле», строка показана как «дополнение»

- **AC-6** (полный дубль)
  - Given: тот же боец с участиями в «Лонгсворде» и «Сабле»
  - When: в файле строка «Иванов Иван; Сталь; Лонгсворд»
  - Then: ничего не меняется, строка показана как «пропуск»

- **AC-7** (дубль внутри файла)
  - Given: в файле две строки про «Петров Пётр» / «Сталь» — с «Лонгсвордом»
    и с «Саблей»
  - When: admin импортирует файл
  - Then: создан один боец с двумя участиями

- **AC-8** (повторная загрузка того же файла)
  - Given: файл успешно импортирован
  - When: admin импортирует тот же файл ещё раз
  - Then: ростер не изменился, все строки показаны как «пропуск»

- **AC-9** (роль)
  - Given: пользователь с ролью `user`
  - When: он обращается к импорту
  - Then: отказ по правам, ростер не изменился

- **AC-10** (лимит)
  - Given: файл сверх лимита размера/строк
  - When: admin загружает его
  - Then: понятная ошибка с указанием лимита, ничего не импортировано

- **AC-11** (номинации по умолчанию из UI)
  - Given: турнир с номинациями «Лонгсворд» и «Сабля»; файл, где у первой
    строки колонка номинаций пуста, а у второй указана «Сабля»
  - When: admin выбирает в диалоге умолчание «Лонгсворд» и импортирует
  - Then: первый боец получает участие в «Лонгсворде», второй — только в
    «Сабле» (умолчание к непустой колонке не добавляется)

- **AC-12** (совпадение с выведенным бойцом)
  - Given: боец «Иванов Иван» / «Сталь» выведен с турнира (травма)
  - When: в файле есть строка про него
  - Then: строка отклонена с причиной «боец выведен с турнира», статус
    бойца и его участия не изменились, остальные строки импортированы

- **AC-13** (нумерация строк в отчёте)
  - Given: файл с заголовком и ошибкой в третьей по счёту строке данных
  - When: admin получает отчёт
  - Then: в отчёте указан номер 4 — та же строка, что видна в редакторе

- **AC-14** (боец без номинаций)
  - Given: файл со строкой «Сидоров Сидор; Меч;» и пустым умолчанием в UI
  - When: admin импортирует файл
  - Then: боец создан без участий, строка показана как «новый боец»,
    ошибкой не считается

## Вне скоупа

- Импорт **заявок** (`application`, 0008/0025) — импортируются бойцы
  ростера напрямую, минуя конвейер рассмотрения заявок.
- Импорт чего-либо, кроме бойцов: номинаций, арен, расписания, результатов
  боёв, пулов и посева.
- Создание номинаций «на лету» из неизвестных названий в файле.
- Настраиваемый маппинг колонок в UI («какая колонка — это имя»): схема
  файла фиксирована шаблоном.
- Экспорт ростера в файл (обратная операция) — отдельная фича.
- Импорт по ссылке/из внешнего API (гугл-таблица, старая система).
- Хранение загруженного файла и история импортов как сущность.
- Откат импорта одной кнопкой («отменить импорт №N»): исправление —
  штатными операциями ростера (снятие/вывод/`MergeFighters`).
- Привязка импортированного бойца к учётке пользователя (`origin_user_id`):
  импортированный боец — всегда «заведён вручную» (`from_application=false`,
  без учётки), как и создаваемый диалогом 0007/0026.
