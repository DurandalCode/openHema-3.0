# Spec: Объяснимый отбор в следующий этап

- Статус: draft
- Дата: 2026-09-25
- Основание: аудит `docs/feedback-audit-2026-09-25.md`, M02/M07/M23/F01;
  существующие правила 0016/0019 и интерфейсы 0032/0051.

> Пакет для согласования. Ниже предложен первый объём: **только admin,
> актуальное превью без сохранения истории оснований отбора**. Пользователь
> ещё не принимал это решение. Plan/tasks — условный проект для оценки
> целиком; они не разрешают реализацию до ответа на вопросы в конце.

## Проблема

Организатор видит отобранные имена, но не имеет рядом сводного рейтинга,
исходных результатов групп и причины решения по каждому участнику.
При ручной проверке основной и утешительной сеток приходится переключаться
между экранами и восстанавливать правило отбора самостоятельно.

## Акторы

- **admin** — проверяет состав перед формированием и разрешает дележи.
- Публичная аудитория в предложенный первый объём не входит.

## Пользовательские сценарии

1. Открыть формирование и увидеть правило, общий рейтинг источника,
   исходные таблицы групп, отобранных и неотобранных с причинами.
2. Объяснить, почему боец с большим количеством очков ниже участника из
   другой группы, почему снятый не проходит и кто занял освободившееся место.
3. Разрешить дележ, перечитать превью и проверить изменившийся состав до
   формирования; не принять порядок строк за спортивный тай-брейк.

## Требования

- FR-1: Превью содержит сводный порядок всех участников исходного группового
  этапа, доступных в его текущих составе/результатах. Видны группа, место в
  группе, общее место, победы/ничьи/поражения, набранные и пропущенные очки.
- FR-2: Порядок соответствует 0019: место в группе, затем победы по
  убыванию, набранные очки по убыванию, пропущенные по возрастанию. Полное
  равенство сохраняет дележ; показатели разных по размеру групп не
  нормируются. Критерии и это ограничение объяснены рядом с таблицей.
- FR-3: Для каждого участника видны решение («проходит», «не проходит»,
  «ожидает решения») и основание: правило отбора, добор вместо неактивного,
  неактивное участие, вне окна отбора, ручной выбор/невыбор при дележе либо
  отсутствие результатов. Неактивность не удаляет сыгранные результаты.
- FR-4: Место в таблице, порядок посева и целевой слот/группа — разные
  значения с отдельными подписями. Ручное разрешение дележа влияет на отбор,
  не переписывает спортивное место. Порядок одинаковых строк по имени/ID
  не представляется спортивным преимуществом.
- FR-5: Результаты исходных групп видны непосредственно в формировании:
  раскрываемые таблицы групп и переход к существующему экрану их боёв.
  В этом предложении «результаты групп» — таблицы, а не второй протокол
  всех отдельных боёв внутри диалога.
- FR-6: Превью явно относится к одному целевому этапу. «Не проходит сюда»
  не означает «выбыл из турнира». Пересечение с другой веткой и превышение
  вместимости показаны как блокировки формирования, отдельно от отбора
  по спортивному правилу; нельзя пометить всех отобранных как уже посеянных.
- FR-7: При незавершённом источнике видны предупреждение и количество
  незавершённых боёв; существующая возможность формирования сохраняется.
  При отсутствии завершённых боёв в группе нет выдуманных нулевых мест:
  для её участников показано «нет результатов для отбора».
- FR-8: После ответа на дележ все таблицы и объяснения обновляются одним
  действием «Обновить превью». Доступно обновление и без дележа; во время
  запроса или после его ошибки старый результат не выдаётся за свежий.
- FR-9: Превью является текущим расчётом, не исторической записью того,
  почему когда-то был сформирован уже изменённый вручную этап. После
  формирования текущий состав остаётся самостоятельным и не пересобирается.
- FR-10: Для источника-ростера показано «все активные участники» без
  выдуманных групповых мест и статистики. Этап без правила сохраняет
  существующий путь ручного набора.
- NFR-1: UI не вычисляет рейтинг или отбор повторно. Чтение объяснений
  не изменяет состав, результаты, правила или ответы на прошлые дележи.
- NFR-2: На 360/390 px таблицы прокручиваются внутри области, основные
  решения и действия доступны с клавиатуры; причины выражены текстом.

## Критерии приёмки

- **AC-1** Given: две завершённые группы и целевой этап с правилом «1–2
  каждой группы». When: admin открывает превью. Then: видны все участники,
  исходные таблицы и объяснения прохода/непрохода; состав совпадает с 0019.
- **AC-2** Given: селектор топ-N сводного порядка и группы разного размера.
  When: показан рейтинг. Then: место в группе первично, абсолютные показатели
  без нормировки; результаты совпадают с вручную рассчитанным эталоном M04.
- **AC-3** Given: полный дележ на границе. When: решения ещё нет, затем
  организатор выбирает и обновляет превью. Then: сначала участники помечены
  как ожидающие решения, затем проход/непроход объяснён ручным выбором;
  спортивные места остались разделёнными. Дележ целиком внутри окна не
  требует решения и не получает ложную пометку «выбрано вручную».
- **AC-4** Given: снятый участник занимал проходное место. When: пересчитано
  превью. Then: его результат и причина исключения видны, следующий
  участник помечен как добор; исходные места не перенумерованы.
- **AC-5** Given: источник недоигран, а в одной группе нет завершённых боёв.
  When: открыто превью. Then: предупреждение видно, группа не исчезла,
  её участникам не присвоены вымышленные места; поведение формирования
  соответствует существующим гейтам 0019.
- **AC-6** Given: пересекающиеся ветки либо отобранных больше вместимости.
  When: открыто превью. Then: объяснение отбора видно, формирование
  заблокировано; UI не изображает несуществующие целевые слоты.
- **AC-7** Given: результаты изменились после первого чтения. When: admin
  обновляет превью. Then: таблицы, причины и назначения сменились вместе;
  ошибка/ожидание не позволяет подтвердить устаревший вид как обновлённый.
- **AC-8** Given: источник-ростер либо этап без правила. When: admin
  работает с составом. Then: нет ложного рейтинга; ручной путь сохранён.
- **AC-9** Given: номинация доступна гостю. When: guest/user пытается
  запросить админское объяснение. Then: доступ отклонён; публичные таблицы
  и сетки продолжают работать в прежнем объёме.
- **AC-10** Given: сформированный этап вручную изменён. When: пользователь
  возвращается к экрану. Then: текущий preview не называется историческим
  основанием существующего состава, сам состав не изменился от чтения.

## Вне скоупа

- Новая формула рейтинга, нормировка, тай-брейки, отмена снятия, смена правил.
- Исторический журнал решений/автора/причин ручного разрешения дележа.
- Публичное объяснение отбора, если отдельно не принято решение ниже.
- Автоматическое обновление сформированного состава, неизменяемый preview
  token и транзакционная фиксация снимка между отдельными RPC.
- Визуальный граф боёв плейоффа — независимая спека 0053.

  да; публичное объяснение добавить отдельно при подтверждённой потребности.
- [ ] D-0054-2: Нужен актуальный расчёт или сохранённые основания каждого
  формирования? Предложение: **актуальный preview без истории**; ручной
  выбор помечается только в текущем цикле preview→build, без автора и даты.

Если требуется public или история, пересмотреть plan/tasks до реализации:
история потребует модели сохранения, а не одной дополнительной подписи.
