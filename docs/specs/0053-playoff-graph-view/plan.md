# Plan: Граф боёв плейоффа

- Статус: ready — включено в независимый запуск; реализация не начата
- Дата: 2026-09-25
- Спека: `./spec.md`

## Обзор решения

Общий read-only renderer находится в `entities/bracket`, поскольку текущий
`features/bracket-seeding/ui/bracket-seeding.tsx` импортирует widget снизу вверх,
нарушая FSD. Новый renderer работает с существующим `Bracket`, считает только
геометрию и соединения, не победителей. DOM-карточки и SVG-рёбра используют
одну модель координат; новая библиотека графов не нужна.

## Контракты (proto)

Без изменений. `proto/hema/v1/stage.proto` уже передаёт круги, половины,
`BracketPair.index`, состояния слотов и бои. `index` глобален внутри круга
и равен номеру выходного слота следующего круга (см. `domain/bracket.go`).
Для чемпионской ветки пара i круга r ведёт к паре ceil(i/2) круга r+1,
нечётная i — сторона A, чётная — B. Бронза — отдельный `thirdPlace`-круг:
два проигравших полуфиналов, а не следующий чемпионский круг.

## Server (модули и слои)

Изменений domain/service/repo/api нет. Используем серверные `resolved`,
`sourceLabel`, `bout`, призёров; клиент не исполняет `ResolveBracket`.
PG-схемы, таблицы, колонки, ограничения, индексы, сиды и миграции не меняются.
Wiring и межмодульные зависимости прежние.

## Web (FSD + BFF)

- BFF/SSR/live-каналы без новых запросов.
- `entities/bracket/lib/graph-layout.ts` + `.test.ts`: чистая модель узлов,
  рёбер (winner/loser), областей половин и кругов; стабильный ключ
  `stageId/round.number/pair.index`, независимо от materialized boutId.
  Сортировка по number/index, не по случайному порядку половин массива.
- `entities/bracket/ui/bracket-graph.tsx` + `.test.tsx`: DOM-карточки,
  серверные подписи, SVG с `aria-hidden`, текстовые описания источников для
  чтения без линий, overflow-контейнер и кнопки перехода к кругам.
- Для согласования высот карточек сначала использовать общую высоту по
  максимальному измеренному содержимому и `ResizeObserver`. Координаты
  вычисляются из измерений, ширины колонок и промежутков. Изменение размера
  шрифта/области вызывает пересчёт; без бесконечного цикла измерений.
  До измерения показывать читаемые карточки без неверных линий. Имена могут
  переноситься; нельзя молча обрезать текст фиксированной высотой.
- `widgets/bracket-view/bracket-view.tsx` остаётся совместимой обёрткой
  над entity для публичной композиции; существующие семантические проверки
  переносятся/расширяются, а не удаляются ради нового DOM.
- `features/bracket-seeding/ui/bracket-seeding.tsx` переключить на entity
  renderer; органы посева и их управление остаются в feature.
- Не менять `widgets/stage-page/stage-page-screen.tsx` и
  `widgets/nomination-public/stage-section.tsx` без обнаруженной необходимости.
  Проверить их интеграцию существующими тестами.
- Client только для измерений/прокрутки. Локальный UI-state/useRef хранит
  viewport; серверные данные остаются у существующих владельцев RQ/live.
  CSS-токены темы; никаких глобальных правок `globals.css` для одного графа.

## События

Новых событий нет. Потребление текущих обновлений остаётся у
`use-bracket-live-sync` и публичного экрана; renderer принимает новые props.

## Тестирование

- Юнит геометрии: 4/8/16/32, порядок половин, winner/loser endpoints, бронза,
  пустые/ожидающие пары, отсутствие пересечения карточек при разных высотах.
- Vitest UI: подписи/счёт/статусы/площадки, accessibility, nav-to-round,
  сохранение scroll на rerender, новые stageId, отключённая бронза.
- Регрессии существующего bracket-view, bracket-seeding и public stage-section.
- Браузерная приёмка AC-6 с реальными размерами: Vitest/jsdom геометрию
  браузера не доказывает. Скриншотные тесты не вводить (ADR 0003).
- Финальная проверка: `make test-all`, в web `pnpm exec tsc --noEmit`,
  `pnpm lint`, `pnpm build`; в server `go build ./...` по DoD.

## Владение, зависимости и параллельность

Владелец трека: новые `entities/bracket/{lib/graph-layout*,ui/bracket-graph*}`,
`widgets/bracket-view/*`, точечный импорт в `features/bracket-seeding/ui/`
и его тест. `entities/bracket/lib/types.ts` — read-only, контракт не расширять.
Трек независим от arena-console, таймера, fighter и серверной работы 0054.
С изменениями самого посева/сброса в `bracket-seeding.tsx` интегрировать
последовательно; общие fixtures и документационные индексы — join координатора.
Renderer не зависит от готовности объяснения отбора и новых исходов.

## Риски и открытые вопросы

- Фиксированная карточка рискует обрезать длинное имя; проверка реальных
  размеров и повторное измерение обязательны.
- Бронзовые линии должны иметь отдельную полосу маршрутизации и подпись
  «проигравшие полуфиналов», без пересечения основного финала.
- При обнаружении недостаточности текущего контракта остановить только
  зависимый шаг, описать конкретный пробел и согласовать расширение с
  владельцем stage.proto; не парсить `sourceLabel` для построения связей.
