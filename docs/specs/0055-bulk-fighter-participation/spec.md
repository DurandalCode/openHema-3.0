# Spec: Массовое добавление существующих бойцов в номинацию

> Артефакт SDD (ADR 0008). ЧТО и ЗАЧЕМ. Источник: аудит M16/F02.

- Статус: draft
- Дата: 2026-09-25
- Решение до реализации: D-BULK

## Проблема

Импорт ускоряет создание ростера, но для уже заведённых бойцов участие приходится
добавлять через отдельные карточки. Нужна операция над явно выбранным составом
без повторного ввода имён, случайного восстановления снятых и изменения посева.

## Акторы

- **admin** — выбирает существующих бойцов турнира и целевую номинацию.
- **user / гость** — массовая операция недоступна.

## Пользовательские сценарии

1. Отфильтровать ростер по клубу, отметить бойцов на нескольких страницах,
   проверить число выбранных и добавить их в одну номинацию.
2. Получить итог по каждому выбранному бойцу: добавлен, уже участвует либо
   отклонён с причиной; после прерванного запроса безопасно повторить действие.
3. Увидеть, что снятого бойца или снятое участие нужно возвращать отдельным
   осознанным действием через существующую карточку.

## Требования

Ниже — **предложение D-BULK**, а не уже согласованное поведение.

- FR-1: Одна операция добавляет явно выбранных бойцов текущего турнира в одну
  выбранную номинацию того же турнира. Она не создаёт новых бойцов.
- FR-2: Выбор сохраняется между страницами одного фильтра. «Выбрать страницу»
  отмечает только загруженную страницу; скрытого «все найденные» нет. Число
  выбранных всегда видно, выбор можно очистить. Изменение поиска, фильтров или
  турнира очищает выбор; смена страницы его сохраняет.
- FR-3: До отправки видны целевая номинация и число выбранных. Повторная отправка
  блокируется пока выполняется текущая. Максимум — 1000 выбранных бойцов.
- FR-4: Результат частичный: ошибка одного бойца не отменяет корректные строки.
  Для каждого уникального выбранного бойца возвращается один итог в порядке
  выбора. Итоги и причины видны в отчёте, число строк равно сумме счётчиков.
- FR-5: Активный боец без участия получает новое участие. Уже активное участие
  остаётся неизменным и отмечается «уже участвует»; повтор не создаёт дублей.
- FR-6: Выведенный с турнира боец, объединённая запись, отсутствующий боец,
  боец другого турнира и снятое участие отклоняются. Массовое добавление не
  восстанавливает снятое участие и не перенаправляет объединённую запись на
  другого бойца. У существующего ручного возврата поведение сохраняется.
- FR-7: Недоступная/чужая целевая номинация, пустой выбор и превышение лимита
  отклоняют запрос целиком до любых изменений. Состояние бойцов проверяется
  заново при применении, а не только при открытии диалога.
- FR-8: Операция меняет только состав номинации. Посев, готовые группы, сетка,
  заявки, оплаты, имя и клуб остаются в ведении соответствующих операций.
  Существующие административные правила добавления в номинацию сохраняются;
  новых ограничений по лимиту участников или приёму заявок не вводится.
- FR-9: После частичного результата ростер обновляется, отчёт остаётся доступен
  до закрытия диалога. Выбор очищается после полученного отчёта; при транспортном
  сбое сохраняется для повторения. Сообщение о сбое не утверждает, что ничего
  не изменилось: часть строк могла уже примениться.
- NFR-1: Только admin; роли проверяются сервером. Никаких прав на массовую
  операцию не появляется у обычного пользователя через прямой запрос.
- NFR-2: Параллельный повтор не дублирует участие и не перезаписывает имя,
  статус, причину снятия или другие участия устаревшим снимком бойца.

## Критерии приёмки

- **AC-1** Given выбор на странице 1; When отметить ещё бойца на странице 2;
  Then действие содержит оба явно выбранных ID, а не весь результат поиска.
- **AC-2** Given непустой выбор; When изменить любой фильтр, поиск или турнир;
  Then выбор очищен. При смене страницы и обновлении данных выбор сохраняется,
  а актуальность бойцов заново проверяется сервером.
- **AC-3** Given активный боец без участия и активный участник; When применить;
  Then первый добавлен, второй отмечен «уже участвует», дублей нет.
- **AC-4** Given выведенный, объединённый, снятый с номинации, отсутствующий,
  чужой и корректный боец; When применить; Then пять строк отклонены с точными
  причинами, корректная применена, снятые не восстановлены.
- **AC-5** Given неверная целевая номинация, 0 или более 1000 ID; When отправить;
  Then понятная ошибка всего запроса, изменений нет. Повторённый ID даёт один
  результат, но не позволяет обойти лимит размера входного запроса.
- **AC-6** Given выполненная операция; When повторить её или отправить два
  одинаковых запроса одновременно; Then ровно одно активное участие на пару
  боец/номинация, остальные участия и данные бойца не изменены.
- **AC-7** Given ошибку транспорта после части применённых строк; When повторить
  сохранившийся выбор; Then ранее применённые строки отмечены «уже участвует»,
  оставшиеся применены либо объяснённо отклонены.
- **AC-8** Given готовая сетка/группы; When добавить участие; Then нет скрытого
  изменения посева и боёв. Given user/гость; When вызвать операцию напрямую;
  Then отказ в доступе без записи.
- **AC-9** Given диалог с частичным результатом; When операция завершена;
  Then видны итоги каждой строки и общие счётчики, данные ростера обновлены,
  клавиатурой доступны выбор, запуск, отчёт и закрытие.

## Вне скоупа

- Массовое создание из файла (уже 0049), массовый возврат/перевод/снятие.
- Автоматический выбор всех результатов поиска, несколько целевых номинаций
  за один запуск, сохранение выбора после перезагрузки страницы.
- Расстановка по пулам/сетке, создание заявок, изменение оплат и тарифов.
- Пересмотр существующей семантики одиночного AddToNomination.
