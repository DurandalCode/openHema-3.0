# Plan: Тарифы — предварительная оценка вариантов

- Статус: draft, **исполняемый план отложен до D-FEE**.
- Спека: [spec.md](spec.md).

## Известная база

`tournament.tournaments` уже хранит `entry_fee_minor` и `entry_fee_currency`.
`application` хранит события подачи/оплаты/регистрации и текущую проекцию заявки,
но не сумму и не совместную стоимость нескольких заявок. Основные контракты:
`proto/hema/v1/tournament.proto` и `application.proto`. Нового server-модуля
заранее не требуется.

## Два разных объёма, которые нельзя смешивать

| Вариант | Что меняется | Что нужно решить |
| --- | --- | --- |
| Информационный расчёт | Правила турнира, отображение цены/основания; текущий payment flow сохраняется | Где показывать, дата/зона, комбинации пакетов; прямо обозначить, что это текущий расчёт, а не сохранённая оплаченная сумма |
| Сохраняемая стоимость и оплата | Версии правил, снимок применённой суммы, связь нескольких заявок, команды оплаты/изменения состава | Объект совместной оплаты, historical/legacy режим, доплаты/возвраты, атомарные изменения заявок, полномочия администратора |

Первоначальный расширенный эскиз заказа не является выбранной архитектурой.
После D-FEE план обязан выбрать один объём; нельзя реализовать корзину лишь
потому, что исходное замечание содержит скидку за две номинации.

## Что дополнить перед ready

1. Сначала proto-контракты и compatibility. Правила `tournament` читаются
   `application` через модульный порт, не cross-schema SQL.
2. Конкретные доменные формулы, границы периодов, округление в minor units,
   максимумы/overflow и применение пакета.
3. Полный DDL по ADR0008: таблицы, типы, CHECK/FK/UNIQUE/индексы/backfill/down.
   Сейчас DDL намеренно не зафиксирован: неизвестно, нужен ли новый объект оплаты.
4. Для варианта оплаты — ADR и таблица command→application event→state,
   однозначный признак legacy/new flow (NULL связи заказа недостаточно),
   атомарность смены состава и запрет обхода через старые endpoints.
5. FSD/BFF: tournament settings, my-applications/application-review только
   если этот объём выбран; auth и расчёт на сервере, UI не источник цены.
6. TDD по выбранным AC, DB concurrent mutations/legacy, API/BFF authorization,
   UI объяснение суммы, migration и integration существующей регистрации.

Это честный блокер планирования, а не задача «пусть модель решит при реализации».
Трек отсутствует в ближайших исполняемых волнах; возврат к нему — после D-FEE.
