## Обзор решения

Чисто web-слой, без proto/server. Два независимых, но связанных куска:

1. **Токены** — существующие shadcn/oklch CSS-переменные в
   `web/src/app/globals.css` перекрашиваются под новую hex-палитру (полный
   ребрендинг, ADR 0015 п.1); добавляются недостающие семантические токены
   (статусы, «приглушённый» текст двух уровней), которых сейчас нет вообще.
   Отдельный `tokens.css` не заводится (см. `web/src/shared/styles/tokens.css`
   в карте дизайн-проекта — это была рекомендация самого дизайн-агента,
   отклонена: два файла токенов усложняли бы правки без выгоды при стратегии
   «рестайлинг на месте»).
2. **12 примитивов** — существующие shadcn-компоненты в `shared/ui`
   рестайлятся на месте (новые варианты/токены, тот же файл/API), примитивы
   без прямого аналога — новые файлы там же. `AppShell` — новая композиция,
   заменяющая текущий тонкий `AdminNav` внутри layout админки.

## Web (FSD + BFF)

### 1. Токены — `web/src/app/globals.css`

Дизайн задаёт hex-палитру с 3 уровнями поверхности, где текущий shadcn-набор
знает только 2 (`background`/`card`≈`popover`). Точное сведение (значения —
из разведки; light-варианты `--bg-surface`/`--bg-raised`/`--fg-muted`/
`--fg-faint`/status-цветов разведка не зафиксировала подетально — **дочитать
конкретные hex светлой темы прямо из `Дизайн-система.dc.html` при
реализации T-задачи токенов, не изобретать**):

| Design-токен | Значение (dark) | → shadcn-переменная | Было (oklch) |
| --- | --- | --- | --- |
| `--bg-page` | `#08080a` | `--background` | `oklch(0.141 0.005 285.823)` |
| `--bg-surface` | `#0d0d11` | `--card`, `--popover` | `oklch(0.21 0.006 285.885)` |
| `--bg-raised` | `#131319` | новая `--surface-raised` (модалки/шапка/dropdown, где нужно визуально отличить от `--card`) | нет аналога |
| `--border` | `#23232b` | `--border`, `--input` | `oklch(1 0 0 / 10%)` |
| `--fg` | `#ece9e4` | `--foreground`, `--card-foreground`, `--popover-foreground` | `oklch(0.985 0 0)` |
| `--fg-muted` | `#8b8b97` | `--muted-foreground` | `oklch(0.705 0.015 286.067)` |
| `--fg-faint` | `#6d6d79` | новая `--caption-foreground` (моно-подписи, JetBrains Mono) | нет аналога |
| `--accent` (красный, бренд/CTA) | `#e2402c` | **`--primary`** (НЕ `--accent`! см. ниже) | `oklch(0.75 0.15 152)` (зелёный) |
| `--danger` | `#ff7a63` | `--destructive` | `oklch(0.704 0.191 22.216)` |
| `--success` | `#5ad18f` | новая `--success` | нет — токена статуса «успех» не было вообще |
| `--info` | `#6ea8fe` | новая `--info` | нет |
| `--warn` | `#f0a04a` | новая `--warning` | нет |

**Важная развилка, найденная разведкой**: shadcn `--accent`/`--accent-foreground`
— это НЕ брендовый цвет, а нейтральная hover/highlight-подложка, реально
используемая 10 файлами (`button`, `dialog`, `dropdown-menu`, `select`,
`skeleton`, `navigation-menu`, `badge`, и 3 фичи) как структурный токен
самих примитивов. Название совпадает с design-токеном `--accent` (красный,
бренд) случайно — переопределение `--accent` в цвет бренда закрасило бы все
hover-подложки красным. Решение: design-`accent` → `--primary`; shadcn
`--accent` остаётся нейтральной подложкой, но пересчитывается под новую
палитру (между `--card` и новой `--surface-raised`), без брендового цвета.

`--gold`/`--gold-foreground` (спека 0004, подиум/медали) — **не трогаем**,
используется в 8 файлах (`tournament-hero`, `nomination-results`,
`bracket-view`, `nominations-list`, `fighter-roster`, `badge`, `about`), вне
палитры дизайн-системы (там нет понятия «золото/подиум»), семантически
самостоятельный токен.

`--sidebar-*` (8 переменных) — сейчас без потребителя (`UiSideNav` не
портируется, ADR 0015 «Границы»). Не трогаем, не удаляем (не в скоупе).

Радиусы: заменить `@theme inline` derived-цепочку (`--radius-sm: calc(var(--radius) - 4px)`
и т.д. от одного `--radius`) на прямые значения дизайна — не выводятся из
одной базы арифметически (6/8/12/16 — не арифметическая прогрессия):

```
--radius-sm: 6px;
--radius-md: 8px;
--radius-lg: 12px;
--radius-xl: 16px;
```

Высоты контролов (30/36/44px — `sm`/`default`/`lg` кнопок и полей), высота
строки таблицы (64px), топбар (50px), заголовок раздела (60px) — новые
токены `--control-h-sm`/`--control-h-md`/`--control-h-lg`/`--row-h`/
`--topbar-h`/`--header-h`, используются соответствующими компонентами
(Button/Field size-вариантами, TableRow, AppShell).

Типографика: Archivo (UI) + JetBrains Mono (моно-подписи) — сейчас в
проекте **нет** ни одного кастомного шрифта (`font-sans` = дефолтный
Tailwind-стек). Подключение через `next/font/google` в `layout.tsx`
(автооптимизация Next, без внешних запросов в рантайме), CSS-переменные
`--font-sans`/`--font-mono` в `@theme inline`, применяются через
`font-sans`/`font-mono` — не отдельными классами, чтобы не трогать разметку
компонентов помимо `body`.

### 2. Примитивы — `web/src/shared/ui/`

| Design-компонент | Файл | Подход | Ключевые изменения |
| --- | --- | --- | --- |
| `UiButton` | `button.tsx` | на месте | +вариант `success`; размеры под `--control-h-*` |
| `UiBadge` | `badge.tsx` | на месте | tone→variant маппинг (`live`→pulse-анимация, `success`/`info`/`warn`/`danger`/`neutral`) |
| `UiTag` | `tag.tsx` (новый) | новый | 5 tone-цветов, без dot/pulse (это Badge) |
| `UiField` | `input.tsx` + `label.tsx` + `select.tsx` | на месте | **не транскрипция**: мок нефункционален (нет `onChange`), реализуется как настоящий контролируемый компонент (`kind: "text" \| "select" \| "search"`) поверх существующих примитивов |
| `UiFilterChip` | `filter-chip.tsx` (новый) | новый | `label`, `count`, `tone`, опциональный dropdown |
| `UiTabs` | `tabs.tsx` | на месте | Radix `Tabs` уже переключает контент по-настоящему (мок — декоративный); визуал под новые токены |
| `UiCard` | `card.tsx` | на месте | +вариант stat-tile (`eyebrow`/`value`/`accent`) |
| `UiEmptyState` | `empty-state.tsx` (новый) | новый | `eyebrow`/`title`/`hint`/`children` |
| `UiModal` | `dialog.tsx` | на месте | рестайл поверх Radix `Dialog` (focus-trap/ESC/ARIA уже есть) — **не** переписывать с нуля как позиционированный `div`, как в моке |
| `UiTableHead` | `table-head.tsx` (новый) | новый | `cols: {label,width,align}[]` — Table-примитива в репо нет вообще |
| `UiTableRow` | `table-row.tsx` (новый) | новый | `cells: {text,sub,width,mono,tone,tags,strike}[]`, `state` (hover/selected) |
| `UiAppShell` | см. «3. AppShell» ниже | новый (композиция) | заменяет `AdminNav` |

`UiFighterCard`, `UiSideNav` — вне скоупа (см. `spec.md`, «Вне скоупа»).

### 3. AppShell — `widgets/admin-shell/` + `shared/ui/app-shell.tsx`

Разделение по FSD (по аналогии с `widgets/navbar`, который уже так устроен):

- `shared/ui/app-shell.tsx` — «глупая» презентационная оболочка (шапка,
  контейнер нав-строки, слоты `crumb`/`title`/`status`/`meta`/`action`/
  `secondary` как пропы), без бизнес-данных.
- `widgets/admin-shell/admin-shell.tsx` (server component) — композиция:
  реальные пункты навигации из `ADMIN_NAV_ITEMS` (переносятся из текущего
  `admin-nav.tsx`, без пункта «Пульт» — фантомный дефолт дизайна, наследие
  архивного Tournament Console, — и с подписью «Площадки», не «Арены»),
  блок пользователя (переиспользует существующий `UserMenu`/аватар из
  `widgets/navbar`, не дублируется).

**Скоуп в 0022 — только шапка+навигация+юзер-блок.** Слоты `crumb`/`title`/
`status`/`meta`/`action`/`secondary` (переменная, специфичная для каждого
экрана часть `UiAppShell`) принимаются компонентом как опциональные пропы
уже сейчас (чтобы не менять сигнатуру на каждой следующей экранной спеке),
но **не заполняются** здесь — их данные появляются вместе с каждым
конкретным экраном (спеки `0024`+).

`widgets/admin-shell/admin-shell.tsx` заменяет использование `AdminNav` в
`src/app/(admin)/admin/layout.tsx` (файл `admin-nav.tsx` + его тест
удаляются, логика активного пункта переезжает в новый widget). Родительский
`(admin)/layout.tsx` (server-side guard) не трогается.

`AdminShell`/`AdminShellLight` (два отдельных компонента дизайна под тему) —
не переносятся как есть: один `AppShell`, тема — через `next-themes`
(ADR 0015 «Границы»).

### 4. Существующие потребители (FR-4/AC-5)

`Navbar`/`AuthDialog`/`UserMenu` (публичная часть, не админка) используют
`button.tsx`/`dialog.tsx`/`badge.tsx` и т.д. — после рестайлинга на месте
обязаны продолжать работать без правок вызывающего кода (пропы не ломаются,
только визуал/токены). Проверяется существующими тестами + ручным смоуком
(см. «Тестирование»).

## Тестирование

> См. ADR 0003 (без скриншот-тестов), `web/AGENTS.md`.

- **Vitest + Testing Library** (новое для `shared/ui`, сейчас там тестов нет
  — компоненты были декларативной вёрсткой без поведения; теперь появляется
  реальная интерактивность):
  - `input.tsx`/`select.tsx` (обновлённый `UiField`-паттерн): контролируемый

  - `dialog.tsx`: закрытие по Escape и клику вне, фокус не покидает модалку,
    пока она открыта (AC-3).
  - `widgets/admin-shell/admin-shell.tsx`: рендерит только реальные пункты
    навигации (нет «Пульт»), активный пункт подсвечен по `pathname` (AC-4) —
    переносит и расширяет существующий `admin-nav.test.tsx`.
- **Регрессия существующих потребителей**: текущие тесты `Navbar`/`AuthDialog`
  (если есть) остаются зелёными без изменений в них самих — ловит поломки
  API рестайленных примитивов (AC-5).
- `pnpm exec tsc --noEmit` — обязательно после правок пропов `shared/ui`
  (сигнатуры компонентов меняются — новые варианты/обязательные пропы).
- Скриншотные/визуальные тесты — осознанно не заводим (ADR 0003); визуальная
  сверка с дизайном — вручную (`pnpm dev`, обе темы) перед завершением.

## Риски и открытые вопросы

- Точные hex светлой темы для `--bg-surface`/`--bg-raised`/`--fg-muted`/
  `--fg-faint`/`--success`/`--info`/`--warning` не зафиксированы разведкой
  построчно — дочитать `Дизайн-система.dc.html` (галерея светлой темы) на
  T-задаче токенов, не оценивать на глаз.
- Пересчёт shadcn `--accent` (нейтральная hover-подложка) под новую палитру
  — решение «между `--card` и `--surface-raised`» ориентировочное, сверить
  визуально с галереей дизайн-системы при реализации (hover-состояния кнопок/
  пунктов меню в обеих темах).
- Высоты контролов (30/36/44) и текущие Tailwind-классы `button.tsx`
  (`h-8`/`h-9`/`h-10` и т.п., если такая схема) могут не совпасть 1:1 —
  свести на T-задаче Button, не постфактум.
- `widgets/admin-shell` — новая директория; проверить, что в `widgets/`
  нет соглашения об index-файле/barrel, которому нужно следовать (см.
  `widgets/navbar/` как образец структуры).
