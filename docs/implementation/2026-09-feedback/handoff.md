# Передача по чатам

## Подготовка координатором

Пока пакет draft, сообщения ниже — заготовки, **не команда начать всё сразу**.
После согласования нужной волны:

1. Записать принятые D-ID, обновить выбранные spec/plan до ready. Прочитать diff
   пакета. Для первого запуска использовать commit публикации документов
   в main; для следующих — базу после интеграции зависимостей. Публикация
   пакета сама по себе не создаёт worktree и не запускает реализацию.
2. Записать фактический base commit выбранной волны. Нельзя использовать
   исходный `3506b03` для исполнения: в нём ещё нет этого пакета.
3. Каждому чату — отдельный worktree и ветка. Например, родительский каталог
   `/private/tmp/hema-feedback/`, ветки `feedback/0052-arena`,
   `feedback/0053-graph`, `feedback/0055-bulk`. Не открывать всем одну checkout.
4. Заполнить шапку сообщения ниже: BASE_COMMIT, WORKTREE, BRANCH, решения.
   Открыть соответствующий worktree в новом чате и вставить содержимое файла.
5. Для поздней волны использовать commit **после мержа её зависимостей**;
   не начинать 0056 с первоначальной базы и надеждой «разрулить потом».

Можно поручить модели несколько последовательных задач одного трека; не нужно
создавать отдельный чат для каждого checkbox. Владельцу нужны цель, границы,
готовые контракты, AC и проверки, а не непрерывные подсказки пользователя.

## Изоляция окружения

- `git status`, текущая ветка и путь проверяются **до изменений**. Не reset/clean
  чужую работу. Каждый commit содержит только файлы своего трека.
- Generated proto/sqlc не переносятся между worktree и не коммитятся.
  `make generate`/`make sqlc` выполняются локально по собственной версии источников.
- Каждый чат использует отдельную тестовую БД/compose project и свободные порты.
  Общий dev/prod DB не мигрировать; нельзя запускать `make dev` нескольким чатам
  на одинаковых портах и считать это независимыми тестами.
- Общий индекс, аудит, решения, волны и номера ADR редактирует координатор.
  Рабочий чат ведёт свой tasks и отдельный отчёт. Новые ADR номера получает
  до работы над файлом, чтобы два чата не создали разные ADR с одним номером.
- Ни один рабочий чат не мержит и не деплоит самостоятельно. Публикация/действия
  на живом турнире не нужны для реализации локальной ветки.

## Что сдаёт каждый чат

Branch/commit и база; выполненные T-ID; список затронутых файлов; какие AC
подтверждены и какими проверками; точные команды и результаты; миграции и
совместимость; открытые вопросы/ограничения. Для непройденного теста — причина,
а не слово «готово». Координатор проверяет diff и стыки, затем интегрирует.

Если появился новый продуктовый вопрос, исполнитель формулирует конкретный
выбор и влияние, продолжает независимые задачи, но не выбирает правило молча.
Рутинные технические решения внутри согласованных границ не требуют повторного
разрешения пользователя.
