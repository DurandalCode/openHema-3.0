## Архитектурные решения перед кодом

Не все технические детали требуют ответа пользователя. Исполнитель готовит ADR
по принятому scope, координатор проверяет; к пользователю возвращаются при
изменении поведения, стоимости/объёма или ограничений совместимости.

- 0052: API переход, current semantics, idempotency/selection guards.
- 0056: durable каскад, восстановление после частичного применения и outcome.
- 0057: явный UoW через модульные порты и единый порядок guard/DB locks;
  нельзя обещать атомарность двух независимых commit.
- 0058: сохраняемые снимки времени и replay журнала, без event sourcing тиков.
- 0060: архитектура только после определения нужного продукта.

## Журнал утверждений

Пока новых утверждений D-ID нет. Координатор добавляет дату, точный принятый
вариант, источник ответа и затронутые документы. Поставить ready всем сразу
на основании общего «давайте подготовим» нельзя.

## Уточнение запуска после подготовки пакета

Пользователь: «давай то что готово без сложного согласования», затем
«ты сам ... не стартуй, делаем максимально параллельно».
Разрешена подготовка независимого запуска; основной чат только координатор.
Выбраны0053, SF-02, SF-04, B03, QA и памятка — см. [launch-now](launch-now.md).
Это **не** утверждение D-API, D-BULK, D-UX или всех остальных D-ID.
Ни один пункт реализации этим не отмечается выполненным.
