# Расписание параллельных волн

**Текущий выбор пользователя:** сначала [шесть независимых чатов](launch-now.md).
Таблица ниже — последующие условные волны, не разрешение запускать их целиком.

Это порядок запуска, а не оценка календарных сроков. Отдельные чаты позволяют распределить работу вне четырёх слотов этого
диалога; доступность сервиса и лимиты аккаунта остаются внешними ограничениями.
Общие файлы и зависимости от этого не исчезают. В каждой строке одновременно работают только перечисленные
непересекающиеся владельцы. Координатор ведёт общую базу и делает join.

этапом относятся к UI-чату волны 2 после проверки; изменения domain SetStatus
согласуются с владельцем 0054 либо ждут завершения его трека.

Владение — на уровне **файлов**, не «backend/frontend» или строк одного файла.
До старта сверять реальные `git diff --name-only` планируемых PR и status базы.
Если новый контракт в процессе трека меняется, сначала интегрировать контракт,
перегенерировать локально, затем продолжать потребителей; не заставлять другой
чат угадывать DTO. При необходимости 0054 можно разделить на backend/frontend
только после contract commit и явного разделения serializer ownership.

## Join каждой волны

1. Проверить diff, AC, отчёты и миграции каждого владельца; сверить продуктовые решения.
2. Интегрировать по одному. После конфликтов повторить проверки затронутых слоёв;
   не выбирать ours/theirs без понимания инвариантов.
3. В общей базе локально сгенерировать proto/sqlc при необходимости;
   выполнить обязательные проверки AGENTS/CI и сценарии стыка этой волны.
4. Только после успеха обновить статусы/аудит и записать base commit следующей волны.
5. Удалять завершённые worktree/ветки только после мержа и проверки отсутствия
   несохранённой работы. Не удалять каталог работающего чата.

Обязательные стыки:0052→0053 live graph;0054→0059 одинаковые данные;
0056→0052/0053/0054/0059 technical winner при противоположном счёте;
0057→0055 конкуренция состава;0058→0052/0056 очередь команд и replay результата.
