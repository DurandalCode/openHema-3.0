# Ручной эталон рейтинга и посева (M04 / Q-RANK)

- Версия проверки: `675bf0b3426ddceff4257d571a21ffb8e53cb8bf`.
- Основание ожидаемых значений: арифметика боёв ниже и правила 0016/0019,
  **до** вызова `ComputeStandings`, `ComputeOverallOrder` и `SelectByRule`.
- Рейтинг: победы ↓, набранные очки ↓, пропущенные ↑. Ничья учитывается в
  столбце Н, очки боя учитываются, но сама ничья не добавляет победу.
  Сводный порядок: сначала место в группе ↑, затем те же три показателя;
  размер группы не нормируется. Полное равенство даёт `1,2,2,4`.

## Основной пример: две группы разного размера

Все перечисленные бои завершены; порядок записи результата — боец слева :
боец справа.

| Группа A, 4 бойца | Результат |
| --- | --- |
| A — B | 3:2 |
| A — C | 4:1 |
| A — D | 2:0 |
| B — C | 2:1 |
| B — D | 2:0 |
| C — D | 2:0 |

| Группа B, 3 бойца | Результат |
| --- | --- |
| E — F | 3:2 |
| E — G | 2:0 |
| F — G | 2:0 |

Ручной подсчёт: у A три победы, очки `3+4+2=9` и
`2+1+0=3`; у B две победы и поражение, очки `2+2+2=6` и
`3+1+0=4`. Остальные строки считаются тем же сложением.

| Боец | В | Н | П | Набрано | Пропущено | Место группы | Место сводное |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| A | 3 | 0 | 0 | 9 | 3 | 1 | 1 |
| B | 2 | 0 | 1 | 6 | 4 | 2 | 3 |
| C | 1 | 0 | 2 | 4 | 6 | 3 | 5 |
| D | 0 | 0 | 3 | 0 | 6 | 4 | 7 |
| E | 2 | 0 | 0 | 5 | 2 | 1 | 2 |
| F | 1 | 0 | 1 | 4 | 3 | 2 | 4 |
| G | 0 | 0 | 2 | 0 | 4 | 3 | 6 |

Порядок сводной таблицы: **A, E, B, F, C, G, D**. E выше B,
хотя у обоих две победы: E первый в своей группе, B второй. Группы
имеют разное число боёв; система сравнивает абсолютные показатели.

Правило основной ветки «места 1–2 каждой группы», сетка на 4:
**A, E, B, F** по сводному порядку. Посев `1×4`:
`A→слот 1`, `E→слот 4`, `B→слот 2`, `F→слот 3`.
Правило утешительной ветки «места 3 и ниже», сетка на 4:
**C, G, D**. Посев: `C→слот 1`, `G→слот 4`, `D→слот 2`;
слот 3 пуст, D получает bye после фиксации сетки. Ветки не пересекаются.

## Полный дележ, ничья и граница отбора

Отдельная группа T с бойцами P, Q, R, S; все шесть боёв завершены:

| Бой | Результат |
| --- | --- |
| P — Q | 2:0 |
| P — R | 2:0 |
| P — S | 2:0 |
| Q — R | 1:1 |
| Q — S | 2:0 |
| R — S | 2:0 |

| Боец | В | Н | П | Набрано | Пропущено | Место |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| P | 3 | 0 | 0 | 6 | 0 | 1 |
| Q | 1 | 1 | 1 | 3 | 3 | 2 |
| R | 1 | 1 | 1 | 3 | 3 | 2 |
| S | 0 | 0 | 3 | 0 | 6 | 4 |

Для окна «места 1–2» P проходит сразу. Q/R делят второе место,
остаётся один слот: превью задаёт `TieAsk{Place:2, SlotsLeft:1}`;
организатор выбирает Q **или** R. Например, ответ с R первым даёт P,R.
ID упорядочивает равные строки воспроизводимо, но не выбирает проходящего.
Для окна 1–3 оба Q/R проходят без вопроса. Если создать вторую идентичную
группу с другими ID, победители делят сводное место 1, четыре вторых бойца
делят сводное место 3, последние — место 7; окно «сводное место 1» требует
решения организатора на границе между победителями.

## Снятие и незавершённый источник

В основном примере снимаем **B**, сохраняя его результаты в таблице. Места
остаются прежними. Основная ветка добирает из группы A следующего активного
бойца **C** и получает `A,E,F,C` в сводном порядке. Правило утешительной
ветки «места 3 и ниже» также видит C. Превью должно показать пересечение C,
а `BuildStage` отказать по 0019 FR-11; организатор должен изменить правила
веток или состав. Это следствие одновременного добора FR-20 и статического
окна второй ветки, не ошибка арифметики рейтинга.

Если в группе A закончен только A—B 3:2, а остальные пять боёв ещё не
завершены, текущая таблица A: `1/0/0, 3:2, место 1`;
B: `0/0/1, 2:3, место 2`; C и D: `0/0/0, 0:0, место 3` у обоих.
Превью предупреждает о **5 незавершённых боях**, но формирование разрешено
по 0019 FR-14. Если в пуле нет ни одного завершённого боя, таблица не
показывается по 0016 FR-7.

Повторное открытие A—B и изменение итога с 3:2 на 1:3 до старта
следующего раунда должно перестроить группу A: B — 3 победы, 7:2,
место 1; A — 2 победы, 7:4, место 2; C и D сохраняют места 3 и 4.
Проверка этого перехода в живой БД/браузере остаётся отдельным сценарием
приёмки: изменение уже сформированной сетки требует осознанного Undo/Build.

## Сверка

На `675bf0b` результаты основного примера, дележа, посева, добора и
пересечения сопоставлены с **выполнением** чистых доменных функций во
временной Go-программе вне репозитория. Точечные существующие unit-тесты и
интеграционный пакет этапов прошли; команды и границы проверки — в
[QA-отчёте](reports/qa.md). Эталон пригоден как вход T0 для 0054 и как
данные визуальной приёмки 0053; технические исходы 0056 добавляются
отдельным примером без изменения этого эталона.
