# Ближайший запуск: независимые задачи без новых бизнес-правил

Пользователь разрешил двигаться с готовыми задачами и уточнил: основной чат
занимается координацией, реализация распределяется по отдельным чатам.
Это не утверждение всех D-ID. Аренный API0052, bulk0055 и другие условные
доменные правила не включены в этот запуск.

## Шесть чатов одновременно

| Чат | Задача | Границы записи | Промпт |
| --- | --- | --- | --- |
| 1 | Граф плейоффа0053 | entities/bracket, bracket-view, bracket-seeding и их тесты по плану | [Граф](chats/0053-graph.md) |
| 2 | Фильтр статуса пулов SF-02 | features/pool-seating/ui/pool-seating.tsx и тест | [Пулы](chats/pools-only.md) |
| 3 | Ошибки диапазона дат при вводе SF-04 | tournament-settings form/screen, при необходимости tournament draft helper и тесты | [Даты](chats/dates-only.md) |
| 4 | Обрезание сотых таймера B03 | features/arena-timer/ui/TimerDisplay.tsx, TimerControls.tsx и их тесты | [Таймер](chats/timer-layout-only.md) |
| 5 | Проверка уже исправленного и ручной эталон рейтинга | Только свой QA-отчёт; продуктовый код не менять | [QA](chats/qa.md) |
| 6 | Черновик памятки секретаря | docs/secretary-guide.md и свой отчёт | [Памятка](chats/guide.md) |

Четыре чата реализуют, два выполняют независимую проверку/документацию.
QA проверяет указанную базу, а не неслитые изменения соседних worktree;
проверка нового совместного поведения выполняется после join.
Памятка описывает текущее поведение; будущий сценарий0052 не выдаётся за готовый.

Чат4 берёт только B03, а не весь0052. Изменения поведения оглашения, API,
очереди команд и источника таймера запрещены в этой задаче. Перед последующим
стартом0052 результат B03 должен быть в его базе; заново чинить геометрию не нужно.
Если для геометрии нужен родитель arena console, чат сообщает координатору
конкретный файл: в этом запуске других владельцев arena console нет.

## Перед открытием рабочих чатов

База первого запуска — commit публикации этого пакета в `main`; публикация
документов не означает принятия отложенных D-ID. Создать шесть отдельных
worktree/веток от этой базы и заполнить шапки промптов
по [handoff](handoff.md). Не запускать шесть чатов в одной папке.

Основной чат не запускает реализацию и не создаёт исполнителей сам. Он принимает
отчёты, проверяет diff/AC, интегрирует по одному и обновляет общий план.
После join повторить затронутые проверки и ручные сценарии, только тогда
отмечать задачи завершёнными.
