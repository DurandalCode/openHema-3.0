# ADR 0024: Очередь пулов на ристалище

- Статус: принято
- Дата: 2026-10-15
- Спека: `docs/specs/0063-arena-pool-queue/`

## Контекст

Ристалище держит ровно один пул (0011). Спека 0043 и ADR 0020 сознательно
ограничили горизонт оценки стоящим пулом и вынесли очередь пулов в «Вне
скоупа» (решение 2026-08-29): порядка «кто за кем» в домене не было.
Полевая практика: план «какие пулы и в каком порядке идут на арене» известен
заранее; без очереди арена простаивает между пулами, а боец не видит, где и
когда его пул.

## Решение

1. **Очередь — упорядоченный план арены**, хранится в `stage.arena_queue`
   (пул → арена, позиция). Пул — не более чем в одной очереди; пул, стоящий
   на арене, в очереди не бывает.
2. **Переход только вручную.** Следующий пул ставит секретарь («Поставить
   следующий»). Автоматической постановки нет — система по-прежнему оценивает,
   но не назначает (ADR 0017 «Границы»).
3. **Горизонт оценки расширен:** стоящий пул **и** очередь неархивной арены.
   Пул очереди стартует, когда по оценке доигрывается предыдущий, плюс
   константа `QueueChangeoverPause` = 5 минут. Оценка по очереди всегда
   предварительная. Это переигрывает 0043 FR-9 и «Вне скоупа» 0043 в части
   очереди; остальная модель ADR 0020 не меняется.
4. В очередь попадают только пулы, доступные для постановки (раскладка этапа
   `ready`). Откат раскладки в черновик блокируется и пулом в очереди.

## Последствия

- Миграция `stage` `00007_arena_queue.sql`; новые RPC `EnqueuePool`,
  `DequeuePool`, `ReorderArenaQueue`, `SeatNextPool`.
- Прогноз 0043 (лента боёв, страница номинации, кабинет, пульт) получает
  время у боёв пулов очереди без правок сборщиков — через общий индекс
  прогнозов.
- Расписание по времени по-прежнему не ведётся.
